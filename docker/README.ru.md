# Зеркало браузера: Neko + Brave

05.10.2026. Один постоянный Brave в Docker. Вы открываете его в обычном браузере (картинка и звук по WebRTC), живёте в нём и логинитесь, а боты и автопрогрев подключаются к тому же Brave по CDP. Общий замысел — [../docs/03-design.md](../docs/ru/03-design.md), выход в сеть через дом — [../docs/05-egress.md](../docs/05-egress.md).

## Быстрый старт (на этой машине)

```sh
cd docker
cp .env.example .env        # заполнить NEKO_PASSWORD и NEKO_ADMIN_PASSWORD (длинные, разные)
docker compose up -d        # только зеркало
./verify.sh                 # проверка: открыть статью из зеркала, прокрутить, убедиться по CDP
```

Открыть `http://127.0.0.1:8080`, имя любое, пароль — `NEKO_PASSWORD`. Управление берётся неявно: навели мышь на видео и работаете. Админ-пароль нужен только для снимка экрана через API.

Остановить: `docker compose stop` (Brave при этом завершается корректно за 1–2 с и сбрасывает cookie на диск). Удалить вместе с профилем: `docker compose down -v`.

## Что проверено на этой машине (05.10.2026)

| Что | Как проверено | Результат |
|---|---|---|
| Neko и Brave поднимаются, порт CDP жив | healthcheck, `./verify.sh` | за 15 с, 750 МБ из 3 ГБ, ~10% процессора в покое |
| Зеркало в браузере показывает живой Brave | вход через Chromium, скриншоты | видео идёт, «You took the controls» |
| Мышь из веб-клиента | клик по подсказке адресной строки | сработал |
| Набор текста из веб-клиента | буквы и точка | сработал |
| Enter, Ctrl+A, Ctrl+L из веб-клиента | **синтетические события моего тестового клиента не доходят** | не доказано для настоящей клавиатуры, см. ниже |
| Управление по протоколу Neko (то, что шлёт веб-клиент) | Ctrl+L, Ctrl+A, набор, Enter, колесо | адрес набран, страница `en.wikipedia.org` загружена из интернета, прокрутка колесом `scrollY=30570` |
| Профиль переживает остановку и пересоздание контейнера | cookie по CDP, `stop/start`, `down/up` | сохраняется, в том числе поставленная за секунду до остановки |
| Автопрогрев в контейнере | `docker compose run life node life.js plan`, подключение по CDP | работает |

**Про Enter из веб-клиента.** Протокол Neko принимает все эти клавиши, и Brave их обрабатывает, но мой тестовый клиент (headless Chromium с синтетическими событиями) Enter и Ctrl-сочетания не передавал, только буквы. Настоящая клавиатура в настоящем браузере должна работать (это штатный сценарий Neko), но я её не проверял. Первое, что сделайте: в зеркале в адресной строке набрать адрес и нажать Enter. Не сработает — напишите, будем разбираться (подозрение на раскладку или на браузер клиента).

## Что пришлось исправить (иначе профиль не жил)

Это не очевидно и стоило часов, поэтому записано:

1. **Cookie стирались при каждой остановке.** В профиле образа стояло «очищать cookie при закрытии» (`cookies: 4`). Теперь профиль принудительно переводится на «сохранять» (`brave-start.sh` и политика `DefaultCookiesSetting`).
2. **Brave не завершался по сигналу.** `/usr/bin/brave-browser` — bash-обёртка, которая запускает настоящий `brave` не через `exec`, и сигнал остановки до браузера не доходил: остановка занимала 18 с (ждали и убивали), а всё записанное за последние секунды терялось. Теперь запускается настоящий бинарник, остановка 1 с.
3. **Клавиатура в зеркале молчала.** В Neko 3 управление по умолчанию нужно просить отдельной кнопкой; включено неявное (`NEKO_SESSION_IMPLICIT_HOSTING`).
4. **Окно «Brave quit unexpectedly»** после каждого пересоздания: перед запуском профиль помечается как чисто закрытый, отчёты о сбоях выключены политикой.
5. **Окно браузера не на весь экран**: размер берётся из `NEKO_DESKTOP_SCREEN`.
6. **Первый запуск тестов зависал машину**: контейнерам заданы потолки памяти и процессора (`NEKO_MEM`, `NEKO_CPUS`), подкачка выключена.

## Что внутри

| Файл | Зачем |
|---|---|
| `docker-compose.yml` | Neko с Brave (`neko`), автопрогрев (`life`, профиль `warmup`), Tailscale (`tailscale`, профиль `egress`) |
| `docker-compose.egress.yml` | поверх основного: Neko и life в сети контейнера Tailscale |
| `neko/brave-start.sh` | запуск Brave: настоящий бинарник, нужные флаги, нормализация профиля |
| `neko/brave.conf` | подменяет конфиг supervisord образа: так Neko принимает флаги браузера |
| `neko/policies.json` | политики Brave (без гостя, без входа, без менеджера паролей, cookie сохраняются) |
| `life/Dockerfile` | образ автопрогрева: Node и Patchright, репозиторий монтируется в `/app` |
| `egress/killswitch.sh` | аварийный выключатель: не-root процессы выходят только через туннель |
| `verify.sh`, `verify/` | проверка зеркала и профиля |

Порт CDP (9222) слушает только внутри контейнера и наружу не публикуется: остальные контейнеры стека делят с Neko сеть (`network_mode: service:neko`).

## Автопрогрев

Сам не стартует (профиль `warmup`): без выхода через Алматы он ушёл бы с адреса сервера.

```sh
docker compose --profile warmup up -d --build     # запустить
docker compose --profile warmup logs -f life      # журнал
docker compose --profile warmup stop life         # остановить
```

Перед первым запуском на сервере создайте `../profiles/egress.json` (`{"country":"KZ","asn":[64500]}`): без него `life` не стартует; с ним перед каждой сессией проверяется выход в сеть, и не из Алматы сессия пропускается. Настройка расписания — [../docs/06-warmup.md](../docs/ru/06-warmup.md).

## Развернуть на сервере

1. Docker и Docker Compose на сервере; Tailscale на хосте (вы уже в одном tailnet с ним).
2. Склонировать репозиторий, `cd docker`, `cp .env.example .env`, пароли.
3. Адреса. В `.env`: `NEKO_BIND_IP` и `NEKO_WEBRTC_IP` — **tailnet-адрес сервера** (`tailscale ip -4`, вида 100.x.y.z). Наружу в публичный интернет порты не открываются. Открывать зеркало с телефона и ноутбука по `http://100.x.y.z:8080`.
4. `docker compose up -d`, затем `./verify.sh persistence`.
5. Выход через дом: поднять exit node на домашнем устройстве ([../docs/05-egress.md](../docs/05-egress.md)), в `.env` задать `TS_AUTHKEY` и `TS_EXTRA_ARGS=--exit-node=<имя узла>`, запустить `docker compose -f docker-compose.yml -f docker-compose.egress.yml --profile egress up -d`. **Не ставьте exit node на сам хост по SSH через публичный адрес** (сессия повиснет): правила и откат — в docs/05.
6. Проверить выход: в зеркале открыть `https://ipinfo.io` — должен быть ваш город и ваш провайдер. Только после этого запускать автопрогрев и ботов.

## Не проверено (только на сервере или руками)

- Enter и сочетания клавиш из веб-клиента с настоящей клавиатурой (см. выше).
- Звук и видео по WebRTC при адресе, отличном от 127.0.0.1 (tailnet): `NEKO_WEBRTC_NAT1TO1` и порты UDP 59000–59019.
- Весь профиль `egress`: сам Tailscale в контейнере, `docker-compose.egress.yml` (описание валидно, запуск не проверялся), цепочка `life → neko → tailscale` в общей сети, аварийный выключатель (не мешает ли он WebRTC, молчит ли браузер при упавшем туннеле), DNS через туннель.
- Скорость и нагрузка на слабом сервере: видео кодируется на процессоре; уменьшайте `NEKO_SCREEN` (по умолчанию 1280x720@30) и `NEKO_CPUS`.
- Регистрация и вход на Tinder, hh и других сайтах из зеркала: сайты могут задавать проверки (SMS, капча); капчу решаете вы, прямо в зеркале.
- Brave на реальных сайтах и сайтах-детекторах.
