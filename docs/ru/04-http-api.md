# HTTP-интерфейс и технический дизайн

05.10.2026. Как проекты работают с браузером: два входа, «видимый HTML» и «действие». Схема, решения и открытые вопросы общего уровня — в [03-design.md](03-design.md).

## Зачем HTTP

Проекты (cvs, tinder-matcher, дальше другие) живут в разных контейнерах и могут быть на разных языках. Вместо библиотеки `require('meatsuit')` у браузера один сервис, к которому подключается кто угодно, даже `curl`. Очередь, лимиты, руки, капча и проверка выхода в сеть остаются в нём. Проект присылает только шаги. Модели в сервисе нет: смотрит и решает вызывающий.

## Два входа

| Вход | Что делает |
|---|---|
| `GET /view` | отдаёт HTML того, что сейчас видно на странице задачи |
| `POST /act` | выполняет одно действие |
| `GET /` | страница статуса для меня: очередь, лимиты, выход в сеть, журнал |

Тело `POST` всегда JSON, `Content-Type` не проверяется. На `/view` и `/act` нужен `Authorization: Bearer <токен клиента>`, а после `begin` ещё `X-Task: <id задачи>`. `GET /` токена не требует: порт всё равно доступен только по tailnet, а страница не показывает ни содержимого страниц, ни введённого текста.

### Задача

```
POST /act {"do":"begin","task":"tinder:like","site":"tinder.com","cost":1}   → {"task":"t42"}
GET  /view        (X-Task: t42)                                                → <html>…</html>
POST /act {"do":"click","target":7}                                           → {"ok":true,"url":"…","guard":null}
POST /act {"do":"end"}                                                        → {"ok":true}
```

`begin`:
1. Встаёт в очередь. Одновременно идёт одна задача. Ждёт своей очереди до `wait` секунд (параметр `begin`, по умолчанию 60), потом отвечает `202` с `ticket`. Повторный `begin` с этим `ticket` сохраняет место.
2. Проверяет выход в сеть (`egress.js`). Не Алматы — `503`, браузер не трогается.
3. Проверяет лимит `site` на сейчас (`sites.json`). Исчерпан — `429` с `retry_at`.
4. Открывает отдельное окно, мои вкладки не трогает.

`cost` (по умолчанию 1) — сколько единиц лимита съедает задача. Сессия из 60 лайков заявляет `cost: 60`.

`end` закрывает окно. Задача, к которой не обращались дольше `idle` минут (по умолчанию 5), закрывается сама, чтобы упавший бот не вешал очередь.

### Статусы

| Код | Когда |
|---|---|
| 200 | сделано |
| 202 | `begin`: пока в очереди, в ответе `ticket` и `position` |
| 400 | запрос непонятен |
| 401 | нет токена или он чужой |
| 403 | сайт не разрешён этому клиенту или не описан в `sites.json`; `goto` за пределы сайтов задачи |
| 404 | цель не найдена |
| 409 `needs_human` | капча, вход или «подозрительная активность». Окно остаётся открытым, чтобы я решил это в зеркале. `POST {"do":"resume"}` перепроверяет и продолжает |
| 410 `stale_ref` | номер элемента устарел, перечитай `GET /view` |
| 422 `ambiguous` | текстовой цели подходит несколько элементов, в ответе кандидаты `[{ref,text}]` |
| 429 | лимит сайта, в ответе `retry_at` |
| 503 `egress_wrong` / `egress_unknown` | выход не из Алматы или не определён |

## Видимый HTML (`GET /view`)

Копия видимого, не живая страница. В DOM браузера я ничего не добавляю, потому что страница увидела бы правки. Номера `data-ms` есть только в ответе.

В ответ попадает:
- заголовок, текст, списки, таблицы, `img` с `alt`;
- ссылки `a[href]`, кнопки, поля и их подписи, `select` с вариантами;
- пароли не отдаются никогда: у `input[type=password]` нет `value`.

Не попадает: `script`, `style`, `noscript`, `template`, скрытое (`display:none`, `visibility:hidden`, нулевой размер, `opacity:0`), содержимое чужих `iframe` (остаётся заглушка `<iframe src>`), закрытые shadow-root.

Номер `data-ms` получают интерактивные элементы: `a`, `button`, `input`, `select`, `textarea`, `[role=button|link|checkbox|…]`, `[tabindex]`, элементы с `cursor:pointer`. Элемент с номером должен реально лежать сверху: `elementFromPoint` в его центре возвращает его или потомка. Иначе кнопку под модальным окном модель «увидела» бы и нажала.

Параметр `?scope=viewport` оставляет только то, что на экране. По умолчанию весь документ.

В `<head>` ответа: `url`, `title`, `guard` (`null` или причина), `egress` (страна и провайдер выхода), а также `scope`, `scroll-y`, `page-height`, `viewport-height`.

Номера живут до следующего `GET /view` или навигации. Номер, которого больше нет, даёт `410`.

Номер → элемент хранится на стороне страницы в изолированном мире Patchright. Если там данные не переживают вызовы, запасной путь: путь по DOM, который пересчитывается при действии. Проверяется в спайке.

## Действия (`POST /act`)

| `do` | Параметры | Как делается |
|---|---|---|
| `begin`, `end`, `resume` | см. выше | жизненный цикл |
| `goto` | `url` | только `http(s)` и только сайты задачи (`site` и его `allow`) |
| `click` | `target` | прокрутка к элементу, мышь по кривой, клик в случайную точку |
| `fill` | `target`, `text` | клик в поле, очистка, если там что-то есть, ввод |
| `type` | `text` | ввод в сфокусированное, по символу, опечатки |
| `key` | `key` | `Enter`, `Escape`, `Tab` и т. п., с короткой паузой |
| `scroll` | `px` (не 0, по модулю до 20000; минус — вверх) или `to:"top"`/`"bottom"` | колесом рывками |
| `back` | | назад по истории |
| `pause` | `from`, `to` (мс) | случайная пауза |

`target` — номер из `/view`, текст (кнопки, ссылки, подписи) или `{"css":"…"}`. Текст ищется только среди видимых: сначала точное совпадение, потом по вхождению.

После действия сервис ждёт, пока страница успокоится: нет навигации и сети около 500 мс, максимум 10 с. Не дождался — `settled:false`, но не ошибка. Запрос держится всё время «человеческого» движения, это секунды.

Ответ: `{"ok":true,"url":"…","settled":true,"guard":null}`.

## Лимиты

`sites.json` как в [03-design.md](03-design.md). Часы в нём по Алматы (`Asia/Almaty`). Единица лимита — `cost` из `begin`. `perDay: 0` значит, что бот на площадке ничего не делает. Счётчики переживают перезапуск.

Площадки не публикуют пороги поведения аккаунта (правила [Tinder](https://policies.tinder.com/terms/intl/en) и [LinkedIn](https://www.linkedin.com/help/linkedin/answer/a1341387) автоматизацию запрещают, чисел не дают), поэтому лимит ведёт себя не ровной планкой, а как человек. Все поля необязательны, без них работает прежняя логика. **Числа ниже мои стартовые допущения, не проверены.**

| Поле площадки | Что делает |
|---|---|
| `ramp: {days, startShare}` | рост: лимит дня = `perDay × (startShare + (1 − startShare) × min(1, d / days))`, где `d` — сутки по Алматы с первого успешного `begin` на этой площадке; округление вверх, не меньше 1. Первый `begin` хранится в `data/limits.json` и забывается, если `begin` вернули (окно не открылось) |
| `restDaysPerWeek` | столько случайных выходных в неделю (неделя с понедельника по Алматы); выбор детерминирован (площадка + номер недели), перезапуск его не меняет; в выходной `429 limit`, `reason: rest_day`, `retry_at` — начало следующих суток |
| `jitter` | дневной лимит умножается на множитель из `[1 − jitter, 1 + jitter]`, одинаковый в течение суток; потолок `floor(perDay × (1 + jitter))`, так что `perDay` становится средним, а не максимумом |
| `challengePauseDays` | `limits.challenge(site)`: после `409 needs_human` (капча, блок, слетел вход) площадка замирает до начала суток по Алматы + N суток: `429 limit`, `reason: challenge_pause`. Пауза переживает перезапуск, повторная проверка её продлевает, но не сокращает |

`GET /` показывает по каждой площадке расход и эффективный лимит сегодня и «выходной день», «пауза до …», «открыта» или «закрыта». При заданных `hours` `retry_at` — первый момент, когда `begin` реально пройдёт.

## guard

Сигналы:
- в DOM или во фреймах: reCAPTCHA, hCaptcha, Turnstile, Arkose;
- адрес вроде `/login`, `/checkpoint`, `/captcha`, `/challenge`;
- текст «unusual activity», «verify you are human», «подозрительная активность», «подтвердите, что вы не робот» и подобные.

Срабатывание: `409 needs_human`, окно остаётся открытым, `notify.js` пишет мне в Telegram, что за сайт и что случилось. Обхода нет. Проверка идёт после каждого `goto`, клика и ввода.

Что построено: `guard.js` с функцией `classify` по снимку `{url, title, text, captchaFrame}`. Фразы и адреса «капча/блок» учитываются только на коротких страницах (до 2000 знаков), фрейм капчи, заголовок 403/429 и адрес входа — всегда. Снимок и поиск фрейма делает `life/probe.js`: reCAPTCHA, hCaptcha, Cloudflare, а с 05.10.2026 и Arkose, DataDome, SmartCaptcha, `#px-captcha`. Теперь `guard` останавливает и сервис (`409 needs_human`, окно открыто, сообщение в Telegram, если он настроен), и `life.js` ([06-warmup.md](06-warmup.md)).

## Выход в сеть: Алматы

IP подделать нельзя: сайт видит адрес реального соединения. Поэтому трафик браузера реально идёт через домашнее устройство в Алматы (exit node Tailscale). Сервер стоит в Нидерландах, в датацентре, и без этого сайты видели бы его.

Сеть контейнеров.
- Compose-стек: контейнер Tailscale с `--exit-node=<домашний узел>`, Neko с Brave и meatsuit в его сетевом окружении (`network_mode: service:tailscale`). Весь трафик браузера, включая UDP и WebRTC, идёт через туннель.
- Туннель упал — сети нет, а не «выход как получится». Запасной путь через голландский IP недопустим. Подстраховка: правило iptables по владельцу процесса: через физический интерфейс может выходить только root (`tailscaled`), браузер нет.
- DNS идёт тоже через туннель, иначе CDN выберет сервер по голландскому резолверу.

Проверка.
- `egress.js` запрашивает адрес выхода у сервиса-эхо (`ipinfo.io`, запасной второй) из той же сети, что и браузер, и сверяет страну и провайдер с `egress.json`: `{"country":"KZ","asn":[64500]}`. Результат кэшируется на минуту.
- Проверка идёт при старте, на каждом `begin` и раз в 5 минут. Не совпало или не определилось — `503`, идущая задача закрывается, `notify.js` пишет мне.

Доступ.
- Зеркало и API доступны по tailnet, наружу порты не открыты.
- Фильм в браузере идёт через домашний канал: нужен upload около 5–8 Мбит/с. Картинка до меня идёт отдельно, прямо с сервера.
- Какое именно домашнее устройство держит exit node, решается отдельно. Эта часть не зависит от остального: меняется только имя узла в compose.

## Фоновая «жизнь» (`life.js`)

Построено как **отдельная команда**, а не часть HTTP-сервиса: сама подключается к браузеру по CDP (`MEATSUIT_CDP` или `--cdp`, по умолчанию `http://127.0.0.1:9222`) и открывает в нём вкладку. Настройка, журнал, разгон и риски — в [06-warmup.md](06-warmup.md); здесь только место в системе.

```sh
node life.js plan          # расписание на сегодня и пример сессии, браузер не нужен
node life.js now [--dry]   # одна сессия сейчас (--dry: показать шаги)
node life.js run           # по расписанию, пока не остановят
```

Конфиг `profiles/life.json` (`tz`, `hours`, `sessionsPerDay`, `minGapMinutes`, `lateMinutes`, `cooldownHours`, `session.minutes`, `session.sites`, `sites`):

```json
{ "tz": "Asia/Almaty", "hours": [9, 23], "sessionsPerDay": [2, 4],
  "session": { "minutes": [5, 12], "sites": [2, 4] },
  "sites": [ { "url": "https://news.ycombinator.com/", "kind": "read",   "weight": 3 },
             { "url": "https://ru.wikipedia.org/",    "kind": "search", "weight": 3, "queries": ["Linux", "Шахматы"] } ] }
```

Что есть:
- случайное число сессий в сутки в окне часов по Алматы, не ближе `minGapMinutes` друг к другу;
- сайты только из `sites`, только `http` и `https`; три вида: `read` (листает колесом, задерживается над текстом по его длине, иногда идёт по ссылке того же сайта), `video` (открывает ролик и ждёт на его странице) и `search` (печатает запрос из `queries` в поле поиска и читает выдачу);
- **ничего не вводит, кроме запроса на сайтах вида `search`, и не нажимает ничего, кроме ссылок и закрытия всплывающего**; входы, регистрации и капчи остаются за человеком;
- `guard` после открытия сайта и после каждого перехода: капча или блок останавливают сессию и ставят паузу на `cooldownHours` (по умолчанию 24 ч, в `profiles/life.json` 72; записывается в `data/life.json`), страница входа пропускает сайт;
- журнал `data/life.jsonl`, повадки `data/persona.json`, состояние `data/life.json`.

Чего ещё нет (и из-за этого `run` пока нельзя оставлять без присмотра рядом с ботами и со мной):

| Задумано | Состояние |
|---|---|
| Самая низкая очередь: уступает любой задаче бота | `queue.js` есть, но прогрев в неё не встаёт; `life.js` про ботов ничего не знает |
| Не стартует, пока я подключён к зеркалу Neko | не сделано, как узнать, см. открытый вопрос 7 в [03-design.md](03-design.md) |
| Не стартует, если выход не из Алматы | **сделано 05.10.2026:** перед каждой сессией выход сверяется с `profiles/egress.json`, не совпал — сессия пропущена; без файла `now` и `run` не стартуют (осознанный обход `--no-egress-check`) |
| Отдельное окно | открывается вкладка в первом контексте браузера |
| Сообщение в Telegram при блоке | `notify.js` есть, но к `life.js` не подключён; запись только в журнале и на экране |
| Работа через `Driver` | подключается сам, напрямую через Patchright |

Моя настоящая жизнь в браузере остаётся главным прогревом, а фон закрывает дни, когда я туда не заходил.

## Журнал

`data/journal.jsonl`: время, клиент, задача, сайт, событие (`begin`, `act`, `end`, `guard`, `limit`, `challenge`, `egress`, `auth`, `notify`, `error`; неудачный `GET /view` пишется как `view`), результат. Тексты полей ввода в журнал не пишутся. Пишет его сервис; прогрев пишет свой, `data/life.jsonl` ([06-warmup.md](06-warmup.md#как-читать-data)).

## Безопасность

Через этот порт можно управлять браузером с моими входами в hh, LinkedIn и почту.
- слушает только localhost контейнерной сети и tailnet;
- свой токен на клиента, `clients.json` вне git;
- `goto` только на разрешённые сайты, только `http` и `https`;
- пароли в `GET /view` не отдаются;
- текст страницы в `/view` — чужие данные: если его читает модель, это забота вызывающего (в tinder-matcher «ворота в коде» уже есть).

## Что построено в `server.js` и чем отличается от спеки

`server.js`, `queue.js`, `limits.js`, `egress.js`, `notify.js` написаны и проверены тестами на подставном `Driver`, без сети и браузера. Живой запуск с настоящим `driver.js` и Chromium (05.10.2026, локальный тестовый сайт «вакансия») прошёл: проверка выхода дала `KZ AS64500`, `begin`, `goto`, `GET /view` (номера у ссылок, поля и кнопки, пароль без значения), `fill` по подписи («Сопроводительное письмо») и `click` по тексту («Откликнуться») сработали, текст дошёл до страницы; `422 ambiguous` со списком кандидатов, `410 stale_ref`, `403` на чужой хост, `409 needs_human` на странице-блоке и отказ действий до `resume`, `401` без токена. Помощник по `driver.js` принял решения: номера хранятся в изолированном мире Patchright (переживают отдельные вызовы, пропадают при навигации), окно задачи создаётся через `Target.createTarget {newWindow: true}` (`context.newPage()` открывает вкладку в чужом окне), вкладка от `target=_blank` становится текущей и по закрытии возвращает к прежней, содержимое iframe всегда заглушка. При реализации приняты решения, которых не было в таблице статусов:

| Что | Как сделано |
|---|---|
| Задача истекла, закончилась или чужая | `404 {"error":"no_task","reason":…}` |
| Порядок проверок | `400`, `403` и `404 site_unknown` приходят до очереди, а не после ожидания слота |
| Площадка закрыта (`perDay: 0`) | `429 closed` с `retry_at: null`; то же без `retry_at` для `too_big` (cost больше лимита) |
| Неверный метод, неизвестный путь | `400`, `404` |
| После `409 needs_human` | действия блокируются до `resume`; на время капчи срок простоя 30 минут вместо 5 |
| `<head>` ответа `/view` | сервер добавляет только `<meta name="egress">`; `url`, `title` и `guard` кладёт `view.js`; `url` и `guard` дублируются заголовками `X-Url` и `X-Guard` |
| `allow` в `begin` | должен входить в список площадок клиента (иначе `403`); клиент со `"*"` допускается на любую площадку из `sites.json` |
| Запасной сервис выхода | `ipwho.is`, а не `ip-api` (тот бесплатно отдаёт только http) |
| `profiles/sites.json` | личный, в git не лежит (обновлено 08.10.2026); образец `profiles/sites.example.json` с площадками `example.com`: числа за меня не выбраны |
| `Driver.view` | получает `{scope: 'viewport' | 'document'}` |
| Потолок действий в задаче (добавлен позже, 05.10.2026) | считаются `goto`, `click`, `fill`, `type`, `key`; сверх `100 + 30 × cost` — `429 limit`, `reason: actions`, окно закрыто, очередь свободна, мне сообщение; дальше задача отвечает `404 no_task`, `reason: actions` |
| Длина `text` у `fill` и `type` | не больше 5000 знаков, иначе `400`: печать идёт с человеческой скоростью |
| Повадки рук | общие с прогревом: `data/persona.json` (`human/persona-file.js`), если у сервиса и `life.js` один каталог `--data` |
| Часовой пояс | `--tz` или `MEATSUIT_TZ` вместо зашитого `Asia/Almaty` |

Переменные окружения: `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`, `MEATSUIT_PORT` (по умолчанию 8787), `MEATSUIT_HOST` (по умолчанию `127.0.0.1`), `MEATSUIT_CDP` (по умолчанию `http://127.0.0.1:9222`), `MEATSUIT_TZ` (пояс для суток и `hours`, по умолчанию `Asia/Almaty`; неизвестное имя — отказ на старте). Те же значения задают флаги `--port`, `--host`, `--cdp`, `--tz`; ещё есть `--data`, `--sites`, `--clients`, `--egress`. Реальные токены клиентов лежат в `profiles/clients.json` (вне git, образец `profiles/clients.example.json`). Выход в сеть проверяется по `profiles/egress.json` (`{"country":"KZ","asn":[64500]}`): файла в репозитории нет, его создаёт тот, кто разворачивает.
