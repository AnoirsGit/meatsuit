# Телефон дома как exit node: первая настройка

Записка для владельца, сверена 21.10.2026. Вспомогательный Android-телефон (модель ещё не выбрана) лежит дома на
зарядке, в интернет ходит **только по Wi-Fi**, Google-аккаунта на нём нет. Он служит exit node Tailscale; `anoir-pc`
остаётся запасным: если телефон пропал, контейнер Tailscale на сервере сам переходит на ПК и возвращается, когда телефон
снова в сети. Как это устроено — [egress.md](../egress.md#fallback-order), здесь только шаги. Основной телефон (iPhone) в
автоматизации не участвует: на нём только VPN и Telegram.

Логины и ключи делаются за одну сессию настройки после прихода телефона (`plans/setup-session.md` в папке проектов
владельца); этот файл — шаги meatsuit из неё.

**Ничего из этого на телефоне ещё не проверено:** его нет. Названия пунктов меню отличаются у разных оболочек Android
(ColorOS, One UI, MIUI и других) и версий; если пункта нет там, где написано, ищите по словам в поиске настроек.

## 1. Tailscale на телефоне

1. Обновить систему. Поставить F-Droid (apk с <https://f-droid.org>), из него — Tailscale: Google Play без аккаунта
   недоступен.
2. Войти в тот же tailnet, что и остальные машины (вход открывается в браузере телефона).
3. В приложении: меню (три точки или «Settings») → **Run as exit node** → включить. Android спросит про VPN — разрешить.
4. В админке <https://login.tailscale.com/admin/machines>, у новой машины в меню «…»:
   - **Edit machine name** → `home-phone` (это имя пойдёт в список на сервере);
   - **Edit route settings** → галочка **Use as exit node**;
   - **Disable key expiry** — иначе через полгода узел выпадет из tailnet.

## 2. Чтобы Android не убил Tailscale

Без этого телефон в первую же ночь «уснёт» вместе с туннелем.

- **Постоянная VPN.** Настройки → поиск «VPN» → Tailscale (шестерёнка) → **Постоянная VPN / Always-on VPN** включить.
  Android сам поднимет Tailscale после перезагрузки или если его убили. «Блокировать соединения без VPN» не нужно.
- **Батарея.** Настройки → Приложения → Tailscale → Батарея: **без ограничений** (фоновая активность разрешена,
  автозапуск разрешён, если такой пункт есть). Если в настройках батареи есть списки «умного энергосбережения» или
  «приложений, которые никогда не засыпают», — Tailscale туда, из «спящих» убрать. Режим энергосбережения не включать.
- **Недавние приложения.** Закрепить карточку Tailscale (замок или «Не закрывать»), чтобы её не смахнула очистка.
- Phantom process killer (Android 12+) убивает дочерние процессы приложений вроде Termux; Tailscale он не касается. Для
  remora (пересылка SMS через Termux) это отдельная история, см. её README.

## 3. Только Wi-Fi

Через exit node трафик должен уходить только по домашнему Wi-Fi. Если телефон молча перейдёт на мобильные данные,
сайты увидят адрес оператора, а не дома.

- **Мобильные данные выключить.** SIM, если стоит, по-прежнему принимает SMS и звонки. Это главная защита: сервер
  проверяет выход раз в ~5 минут, и между проверками трафик через оператора был бы не замечен.
- **Переключение на мобильную сеть выключить:** в настройках Wi-Fi («Дополнительно», «Wi-Fi-ассистент» и т. п.) всё
  вроде «Переключаться на мобильные данные», «Автопереключение на мобильную сеть», «Двухканальное ускорение» — выкл.
- **Wi-Fi во сне:** если есть «Wi-Fi в спящем режиме» — «Всегда».
- Держать ближе к роутеру.

## 4. Зарядка круглые сутки

Включить защиту батареи, если она есть («Защита аккумулятора», «Оптимизированная зарядка», предел 80–85 %). Класть не на
мягкое и не под солнце.

## 5. Сервер

Деплой — владелец (или по его «да»). Клон на боксе (`/opt/meatsuit`) стоит на ветке `ms-trunk`: там ещё нет
`docker/egress/exit-picker.sh`, ревью скрытности и `extras/` в нынешнем виде. Сначала `main` должен быть запушен
(и, если идёт переписывание истории, — переписан: скрипт чистки сам сбрасывает клон на боксе на `origin/main`).

**1. Клон на `main`.** Файл деплоя `docker/.env` и `profiles/` в git не входят и не меняются.

```sh
cd /opt/meatsuit
git status --short                 # пусто (неотслеживаемые profiles/ и docker/.env не в счёт)
git fetch --prune origin
git checkout -B main origin/main
```

Без новых строк в файле деплоя `main` работает как `ms-trunk`: `exit-picker.sh` только запускает Tailscale, выход — тот
узел, что в `TS_EXTRA_ARGS`.

**2. Список узлов.** В `/opt/meatsuit/docker/.env` добавить три строки, `TS_EXTRA_ARGS` не трогать (при старте нужен
адрес, имя там не принимается):

```sh
MEATSUIT_EXIT_NODES=home-phone,anoir-pc
MEATSUIT_EXIT_COUNTRY=<страна>      # с домашнего Wi-Fi открыть https://ipinfo.io/json: поле country
MEATSUIT_EXIT_ASN=<номер>           # там же: число из поля org после «AS»; несколько — через запятую
```

Заодно проверить `MEATSUIT_TZ` (`grep MEATSUIT_TZ docker/.env`): там должен быть пояс страны выхода, а не `UTC` по
умолчанию — сайт сверяет пояс браузера с адресом. У вызывающих тот же пояс: `TIMEZONE` в `deploy/.env` tinder-matcher,
`TZ` сервиса `apply` у cvs (по нему считаются часы `hours` их `sites.json`). В админке Tailscale этот сервер — машина
с именем из `TS_HOSTNAME` (по умолчанию `meatsuit`), контейнер — `meatsuit-tailscale-1`.

**3. Пересоздать стек:** Tailscale и всё, что живёт в его сети (браузер, прогрев и HTTP-сервис, если включены; профиль в
томе не пропадает):

```sh
docker/up.sh up -d --force-recreate
```

**4. Пересоздать соседей.** То, что подключено к браузеру через `container:meatsuit-browser` и живёт постоянно, со
старым сетевым окружением остаётся без сети. `docker/up.sh` после такого `up` сам печатает их список с командой для
каждого (сам их не пересоздаёт). Найти их и руками:

```sh
docker ps -q | xargs docker inspect --format '{{.Name}} {{.HostConfig.NetworkMode}}' | grep 'container:'
```

Каждый из списка пересоздать в его проекте (`docker compose … up -d --force-recreate <сервис>`). У cvs команда зависит
от того, какой автоотклик слит (решение владельца ещё не принято): с сервисом `apply` из веток `agent/cvs-*` —
`cd /opt/cvs && docker compose --profile apply up -d --force-recreate apply`; на нынешнем `main` cvs подключается
файлом `docker-compose.meatsuit.yml` — тогда `docker compose -f docker-compose.yml -f docker-compose.meatsuit.yml
--profile telegram up -d --force-recreate jobs`.

Бот tinder-matcher (`deploy/run.sh` → `docker compose run --rm matcher`) — новый контейнер на каждый запуск cron, сам
берёт новое сетевое окружение; его `pult` и `ui` живут в своей сети, их пересоздавать не нужно.

Если в `profiles/egress.json` (прогрев и HTTP-сервис из `extras/`) записаны номера провайдеров — там должен быть только
домашний, не мобильный.

## 6. Проверка

1. `docker/up.sh exec tailscale sh /exit-picker.sh status` — у `home-phone` в колонке chosen `yes`, в probe
   `ok <страна> <номер>`, внизу `gate: open`.
2. В зеркале открыть <https://ipinfo.io>: страна и провайдер домашние.
3. Учебная тревога: на телефоне выключить Wi-Fi. Через несколько минут `docker/up.sh logs --tail 20 tailscale` пишет
   `exit-picker: exit node: anoir-pc (…)`, в зеркале ipinfo по-прежнему домашний. Включить Wi-Fi: минуты через две после
   того, как телефон снова в сети, выход вернётся на него.
4. Скорость: шаг 5 «Verify» в [egress.md](../egress.md#verify) — через телефон, потом через ПК; записать обе цифры.
5. Если `gate: closed` и браузер без сети: ни один узел не прошёл проверку. Смотреть `status` (колонка probe) и логи:
   `wrong … AS <номер оператора>` — телефон ушёл на мобильные данные (шаг 3); `unknown` — дом без интернета или
   ipinfo/ipwho.is недоступны.

Результат учебной тревоги записать в egress.md, «What is verified and what is not», и закрыть пункт в
[ROADMAP.md](../ROADMAP.md).
