# Как всё работает на десктопе

Это про запуск meatsuit на вашем компьютере (не на сервере). Рабочая записка на русском. Что проверено, а что нет,
написано рядом с каждым пунктом. Общая картина проекта: [03-design.md](03-design.md), HTTP-интерфейс:
[04-http-api.md](04-http-api.md), прогрев: [06-warmup.md](06-warmup.md), Docker: [../../docker/README.ru.md](../../docker/README.ru.md).

## Коротко

На десктопе meatsuit это **один браузер в Docker, ваши скрипты и прогрев вокруг него**. Ваш обычный Brave, которым вы
пользуетесь каждый день, тут не участвует: в контейнере стоит отдельный Brave со своим профилем.

```
 ваш десктоп
 ┌──────────────────────────────────────────────────────────────────────────────┐
 │  вы: вкладка браузера ──► http://127.0.0.1:8080  (зеркало Neko, картинка и звук)│
 │                                     │                                         │
 │                          ┌──────────▼───────────┐                             │
 │                          │ контейнер neko       │  профиль браузера           │
 │                          │ Brave, порт CDP 9222 │  в томе Docker              │
 │                          └──────▲───────▲───────┘                             │
 │        общая сеть контейнеров   │       │                                     │
 │   ┌─────────────────────────────┴─┐   ┌─┴───────────────────────────┐         │
 │   │ server (профиль api)          │   │ life (профиль warmup)       │         │
 │   │ GET /view, POST /act :8787    │   │ прогрев: читает сайты       │         │
 │   │ очередь, лимиты, проверка     │   │ как человек, по расписанию  │         │
 │   │ выхода, человеческие руки     │   └─────────────────────────────┘         │
 │   └──────────────▲────────────────┘                                           │
 │                  │ ваши скрипты (curl, Node, Python…)                         │
 └──────────────────┼────────────────────────────────────────────────────────────┘
                    └── весь трафик браузера выходит через домашний интернет
```

Дома отдельный слой «выход через дом» (Tailscale) **не нужен**: компьютер и так стоит дома, трафик идёт с вашего
домашнего адреса. Этот слой нужен серверу, чтобы он выходил из вашего дома.

## Что нужно на компьютере

- Node 20 или новее и `npm install` в корне репозитория (ставит Patchright).
- Docker с Compose (v2.24 или новее для файла `docker-compose.egress.yml`; для десктопа он не нужен).
- Для тестов на настоящем браузере: системный Chromium (`/usr/bin/chromium`; другой путь — в `MEATSUIT_CHROMIUM`, а для e2e
  в `CHROMIUM`). Patchright сам браузер не скачивает.

## Запуск зеркала

```sh
cd docker
cp .env.example .env        # задать NEKO_PASSWORD и NEKO_ADMIN_PASSWORD: длинные, разные, без пробелов и знака $
docker compose up -d        # первый раз качает образ Neko с Brave (на диске около 2,3 ГБ)
./verify.sh                 # сам открывает статью в зеркале, прокручивает и проверяет по CDP
```

Потом откройте `http://127.0.0.1:8080`, имя любое, пароль из `.env` (`NEKO_PASSWORD`). Вы увидите живой Brave.
Входите на сайты руками: профиль хранится в томе Docker и переживает остановку и перезапуск.

| Что | Команда |
|---|---|
| Остановить (профиль и входы сохраняются) | `docker compose stop` |
| Запустить снова | `docker compose start` |
| Посмотреть журнал | `docker compose logs -f neko` |
| Стереть всё, **включая профиль браузера и входы** | `docker compose down -v` |
| Проверить, что профиль переживает остановку | `./verify.sh persistence` |

Ограничения контейнера по умолчанию: 3 ГБ памяти и 2 ядра. Если компьютер тормозит, уменьшите `NEKO_SCREEN`
(по умолчанию `1280x720@30`) и `NEKO_CPUS` в `.env`.

Проверено на этом компьютере: старт и здоровье, показ живого Brave в зеркале, мышь и ввод букв из веб-клиента,
прокрутка, профиль переживает остановку и пересоздание. **Не проверено:** Enter и Ctrl-сочетания настоящей клавиатурой
в веб-клиенте (тестовый клиент слал синтетические события, и они не дошли), звук.

## Скрипты: HTTP-интерфейс

Ваши скрипты работают в том же браузере через два входа (подробно в [04-http-api.md](04-http-api.md)):

- `GET /view`: видимый HTML страницы, у каждого интерактивного элемента номер `data-ms`;
- `POST /act`: одно действие (`begin`, `goto`, `click`, `fill`, `type`, `key`, `scroll`, `back`, `pause`, `resume`, `end`).

Перед запуском нужны три файла в `profiles/`:

| Файл | Что в нём | В git |
|---|---|---|
| `clients.json` | кто может звать: `[{"name":"my-bot","token":"<длинная случайная строка>","sites":["example.com"]}]`, токен из `openssl rand -hex 24` | нет |
| `sites.json` | лимиты площадок (образец уже лежит): `perDay`, `perHour`, `hours`, рост, выходные. `tinder.com` и `linkedin.com` стоят с `perDay: 0`, то есть закрыты, пока вы сами не откроете. Площадку, которой нет в файле, сервис не откроет никому (`403`, `reason: site_unknown`), поэтому для пробы ниже допишите `"example.com": { "perDay": 50 }` | да |
| `egress.json` | выход, который вы ожидаете: `{"country":"KZ","asn":[<номер провайдера>]}`; страна и номер из `curl -s https://ipinfo.io/json` | нет |

`profiles/egress.json` и `profiles/clients.json` содержат ваши данные и в репозиторий не попадают.

Запуск сервиса в контейнере, рядом с браузером (CDP наружу не публикуется, поэтому с хоста до него не достать):

```sh
cd docker
docker compose --profile api up -d --build
curl -s http://127.0.0.1:8787/                      # страница статуса, токен не нужен
```

Пример задачи (токен ваш):

```sh
TOKEN=...   # из clients.json
H="Authorization: Bearer $TOKEN"
curl -s -H "$H" -d '{"do":"begin","task":"demo","site":"example.com"}' http://127.0.0.1:8787/act     # -> {"task":"t1"}
curl -s -H "$H" -H "X-Task: t1" -d '{"do":"goto","url":"https://example.com/"}' http://127.0.0.1:8787/act
curl -s -H "$H" -H "X-Task: t1" http://127.0.0.1:8787/view
curl -s -H "$H" -H "X-Task: t1" -d '{"do":"end"}' http://127.0.0.1:8787/act
```

Что делает сервис, чтобы вас не заблокировали: одна задача за раз (остальные в очереди), лимиты как у человека,
потолок действий в задаче, перед каждой задачей проверка выхода (не тот выход, и задача не начнётся), остановка на
капче, блоке и странице входа с ответом `409 needs_human` (решаете вы, в зеркале, потом `resume`). Мышь, клавиатура
и колесо двигаются с человеческим темпом.

**Состояние проверки:** HTTP-интерфейс на локальном тестовом сайте в настоящем Chromium прошёл (live-прогон, тесты).
Запуск сервиса **в контейнере** (профиль `api`) не проверялся: `docker compose config` его принимает, но контейнер не
стартовал. На реальных сайтах не проверялся.

Быстрая проба без Docker, с любым Chromium на компьютере (проще, но это не тот браузер, в котором вы живёте):

```sh
chromium --remote-debugging-port=9222 &
node server.js --cdp http://127.0.0.1:9222
```

## Прогрев

Прогрев сам ходит по обычным сайтам в случайные часы и читает их как человек (листает, иногда идёт по ссылке,
закрывает баннер cookies, ищет на Википедии). Только читает, никуда не входит. На капче и блоке замолкает на несколько суток
(`cooldownHours` в `profiles/life.json`, сейчас 72 ч).

```sh
node life.js plan                 # расписание на сегодня и пример сессии, браузер не нужен
node life.js now --dry            # показать шаги, ничего не открывая
cd docker && docker compose --profile warmup up -d --build     # работать по расписанию в контейнере
docker compose --profile warmup logs -f life                   # журнал
```

Прогрев **не стартует без `profiles/egress.json`** (иначе он мог бы нагулять историю с чужого адреса). Осознанно
обойти можно флагом `--no-egress-check`, но для рабочего профиля не стоит. Список сайтов и числа в
`profiles/life.json` мои стартовые догадки, не измеренные; YouTube в нём нет (вход в Google заполнил бы историю
просмотров аккаунта). Ваша настоящая жизнь в браузере это основной прогрев, автоматический только добавка.

**Не проверено:** прогрев на реальных сайтах и неделями.

## Тесты и нагрузка

```sh
scripts/capped npm test            # все тесты под потолком памяти и процессора (3 ГБ, 200%)
scripts/capped npm run test:e2e    # сквозной тест на настоящем Chromium, около двух минут
```

Тесты идут **по одному файлу**, и это нарочно: компьютер три раза зависал от нескольких Chromium и Docker
одновременно. Не запускайте тесты с поднятым зеркалом и вторым браузером параллельно. Тесты с браузером сами
пропускаются, если Chromium или Patchright не найдены. Последний полный прогон (07.10.2026): 400 прошли, 1 пропущен
(это e2e, без `E2E=1` он не идёт), 0 упало, около полутора минут; e2e 8 из 8.

## Где что лежит

| Что | Где |
|---|---|
| Профиль браузера (куки, входы, история) | том Docker `meatsuit_brave_profile` (`docker volume ls`) |
| Журнал и состояние прогрева, повадки рук | том `meatsuit_life_data`: `life.jsonl`, `life.json`, `persona.json` |
| Журнал и счётчики сервиса в Docker (профиль `api`) | тот же том `meatsuit_life_data`: `journal.jsonl`, `limits.json` |
| Журнал и счётчики сервиса при запуске без Docker | `data/` в репозитории (`journal.jsonl`, `limits.json`, `persona.json`), в git не попадает |
| Пароли зеркала | `docker/.env`, в git не попадает |
| Токены клиентов, ожидаемый выход | `profiles/clients.json`, `profiles/egress.json`, в git не попадают |

## Если что-то не так

| Симптом | Что сделать |
|---|---|
| Зеркало не открывается | `docker compose ps` и `docker compose logs neko`; здоровье требует и веб-часть Neko, и порт CDP |
| Компьютер подтормаживает | уменьшить `NEKO_SCREEN`, `NEKO_CPUS`, `NEKO_MEM`; тесты только через `scripts/capped` |
| Прогрев или сервис не стартуют, пишут про `egress.json` | создать файл (страна и номер провайдера по `ipinfo.io`) или осознанно `--no-egress-check` для прогрева (у сервиса такого флага нет; у контейнера `life` команда записана в `docker-compose.yml`, флаг пришлось бы дописать туда) |
| Ответ `503 egress_wrong` | выход не тот, что в `egress.json`: проверьте, не включён ли VPN, и `curl -s https://ipinfo.io/json` |
| Ответ `503 egress_unknown` | выход не определился: не ответили ни `ipinfo.io`, ни `ipwho.is` (или в `egress.json` есть `asn`, а сервис номер не назвал); проверьте интернет |
| Ответ `409 needs_human` | в зеркале открыта капча, блок или страница входа: решите руками и позовите `resume` |
| Ответ `429 limit` | сработал лимит площадки; в ответе `reason` и время `retry_at`. `reason: actions` значит другое: задача упёрлась в потолок действий (`100 + 30 × cost`), окно уже закрыто, нужен новый `begin` |
| `docker compose up` не подхватил правку скрипта в `docker/neko/` | нужен `docker compose restart neko`: контейнер не пересоздаётся, если поменялся только смонтированный файл |

## Что на десктопе не проверено вообще

- Enter и сочетания клавиш настоящей клавиатурой в зеркале, звук.
- Сервис `server` (профиль `api`) в контейнере.
- Brave на реальных сайтах и на сайтах-детекторах; регистрация и вход на Tinder, hh и других из зеркала.
- Прогрев неделями.
- Как конкретная площадка отреагирует: проект этого не обещает.
