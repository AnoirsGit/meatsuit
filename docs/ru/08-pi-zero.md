# Raspberry Pi Zero W как домашний exit node: что подготовлено и на чём споткнулись

10–11.10.2026. Записка для владельца и следующих сессий. Зачем это вообще и какие ещё были варианты, сказано в
[05-egress.md](../05-egress.md) (вариант B). Здесь: что сделано, что не получилось и почему, и что осталось до запуска.

## Итог 16.10.2026: эта плата для exit node не годится

- **Карта рабочая.** Новая microSD на 64 ГБ (124 964 864 сектора, видна как 59,6 ГиБ). Образ записан через PocketBook
  по порядку ниже, сверка мимо кэша (`compare-sd.sh`): 0 из 42 кусков по 64 МиБ отличаются. Весь объём `f3probe` не
  проверяли.
- **С карты Pi не загружается.** 10 минут на питании, затем карта прочитана в PocketBook только на чтение: раздел
  `rootfs` не расширен (2,1 ГБ), имя хоста `raspberrypi`, `/var/lib/cloud` нет, журналы пустые. Linux до корневого
  раздела не дошёл. Диод при этом не горит. С картой Pi не уходит в загрузку по USB, без карты уходит
  (`0a5c:2763 BCM2708 Boot`): значит, карту он не читает до конца, а зависает на ней. Вероятная причина — слот или его
  контакты (плату трогали гости), образ и карта проверены.
- **Wi-Fi мёртвый.** Linux, загруженный по USB (`rpiboot` + `linux-msd/`), с полной прошивкой `43430` и калибровкой
  `model-zero-w.txt`: модуль поднимается (шаг 4), но сеть `Niorio` не находит (частое мерцание, `NOTFOUND`), а свою
  точку доступа с диагнозом в имени не показывает: ПК в метре её не видит, хотя «Niorio» ловит на 44 %. 10.10, до
  гостей, было то же самое, так что это похоже на брак, а не на слабый сигнал.
- **Что живо.** Процессор, память, USB: загрузка по USB с ПК работает.
- **Решение владельца.** Плату вернуть продавцу как брак или продать как неисправную. Exit node — **Orange Pi Zero 3
  (1 ГБ)** с Ethernet в роутер, заказ с AliExpress. Ошибка выбора: в [05-egress.md](../05-egress.md) вариант B был
  назван «Raspberry Pi» без требования Ethernet, а Zero W для круглосуточного exit node — худший вариант (одно ядро,
  только Wi-Fi 2,4 ГГц, хрупкие слот и разъёмы).

### На что пригодится карта на 64 ГБ

- **Системный диск Orange Pi Zero 3.** Основное назначение. Образ нужен другой (Armbian или Debian для Orange Pi),
  записывать так же через PocketBook со сверкой мимо кэша.
- **Pi-hole рядом с exit node** на той же Orange Pi: места и памяти хватает. Блокирует рекламу и трекеры по DNS для всей
  домашней сети; YouTube и рекламу в лентах соцсетей не убирает. Терминал Huawei может не дать сменить DNS для сети —
  тогда DHCP на Pi-hole или DNS вручную на устройствах.
- **Запас.** Книги в PocketBook, память телефона или камеры: карта обычная, SDXC с exFAT после форматирования.

## Коротко (10–11.10)

- **Цель.** Pi Zero W круглосуточно стоит дома у роутера и служит exit node Tailscale вместо `anoir-pc`. Браузер meatsuit
  на сервере выходит в интернет через него, с домашнего адреса. Тогда боты (cvs, tinder-matcher) работают, даже когда ПК
  выключен.
- **Образ для карты готов** (Raspberry Pi OS Lite, настройка первого запуска через cloud-init). Он лежит на `anoir-pc`
  вне репозитория, см. «Где что лежит».
- **Карты пока нет.** Первая карта мёртвая. Вторая, «новая на 8 ГБ», оказалась поддельной: настоящий объём около 122 МБ.
  Нужна настоящая microSD.
- **Чем записать карту.** Картридера нет. Работает PocketBook 628 в режиме «Связь с ПК», с одной хитростью (ниже).
  Записать карту через сам Pi по USB с этого ПК не вышло.
- **Главный риск после запуска — Wi-Fi.** У Pi рядом с ПК не получилось подключиться к домашнему Wi-Fi. Причина не
  установлена; вероятно, слабый сигнал. Ставить Pi ближе к роутеру.

## Железо

- **Плата.** Raspberry Pi Zero W: одно ядро ARMv6, 512 МБ памяти, Wi-Fi только 2,4 ГГц, Ethernet нет.
- **Два порта micro-USB.** Средний («USB») — данные, через него ПК видит плату. Крайний («PWR IN») — только питание.
- **Как Pi будет стоять.** В розетке от отдельной зарядки 5 В не меньше 1 А, через PWR IN, рядом с терминалом. От
  USB-порта ПК его питать нельзя: выключится ПК — пропадёт и exit node.
- **Wi-Fi.** На Zero W он слабый. Трафик exit node проходит через радио дважды: из туннеля и в интернет. Хватит ли
  скорости на нужные «около 8 Мбит/с вверх», **не измерено**.
- **MAC платы начинается на `b8:27:eb`.** По нему её ищут в домашней сети: `ip neigh` после пинга всей подсети.

## Образ для карты

- **Основа.** Raspberry Pi OS Lite, **32-bit** (armhf, trixie, выпуск 2026-10-06), с сайта Raspberry Pi; контрольная
  сумма сверена. 64-битный образ на Zero W не запустится.
- **Настройка первого запуска — cloud-init.** В этой версии системы Imager пишет на загрузочный раздел файлы
  `user-data`, `network-config` и `meta-data`; старый `firstrun.sh` больше не используется. Что прописано:
  - **Имя и пользователь.** Имя `home-exit`. Пользователь `anoir`: вход только по SSH-ключу с `anoir-pc`, пароля нет,
    `sudo` без пароля. Пароль по SSH выключен (`ssh_pwauth: false`).
  - **Wi-Fi.** Домашняя сеть в `network-config` (netplan v2, NetworkManager), `regulatory-domain: KZ`. **Имя сети
    чувствительно к регистру**: сначала оно было записано с маленькой буквы, и из-за этого Pi сеть не находил.
  - **Страна Wi-Fi.** В `cmdline.txt` добавлено `cfg80211.ieee80211_regdom=KZ`. В `runcmd` стоит
    `imager_custom set_wlan_country KZ`: это официальный помощник Raspberry Pi, он же снимает блокировку Wi-Fi.
  - **SSH.** Пустой файл `ssh` на загрузочном разделе, плюс `imager_custom enable_ssh -k` и `systemctl start ssh`.
  - **Запасной вход по USB.** `dtoverlay=dwc2` в `config.txt` и `modules-load=dwc2,g_ether` в `cmdline.txt`. Если Wi-Fi
    не поднимется, Pi можно воткнуть средним портом в ПК и зайти по SSH через USB-сеть (адрес IPv6 link-local). На
    практике пока не проверено.
  - **Чего в образе нет.** Tailscale и прочую настройку не ставили в образ намеренно: это делается по SSH после
    загрузки, чтобы видеть ошибки.
- **Пароль Wi-Fi лежит открытым текстом** в `network-config` на загрузочном разделе: так устроен cloud-init. После
  первого запуска файл можно удалить, подключение NetworkManager уже сохранено.
- **Как собирали образ без root.** Через `udisksctl loop-setup` и `udisksctl mount` (polkit разрешает это активному
  пользователю). Правка файлов на загрузочном разделе — обычной записью.

## Чем писать карту

### PocketBook 628 вместо картридера — работает, с одной хитростью

В режиме «Связь с ПК» PocketBook отдаёт компьютеру два диска. LUN 0 — своя память, около 6,5 ГБ, метка `PB628`; её не
трогать. LUN 1 — карта. Сначала выбрать режим на экране книги, иначе устройство подключается и сразу отваливается.
На `anoir-pc` книга надёжно работает в порту `1-6`. В порту `1-9` отваливалась через долю секунды; в этот же порт
раньше был воткнут Pi.

**Хитрость.** Если на карте есть файловая система FAT, PocketBook держит её смонтированной у себя. Пока идёт запись
образа, он сбрасывает свою старую таблицу FAT поверх новых данных. Первая запись так и испортилась: в первых 8 МиБ
лежали записи FAT вместо нулей образа. Порядок, который работает:

1. **Затереть начало карты.** Записать нули в первые 64 МиБ (`dd if=/dev/zero bs=4M count=16 conv=fsync`, нужен root:
   `pkexec`).
2. **Переподключить книгу.** Отключить и снова включить «Связь с ПК»; на «отформатировать карту?» отвечать «Нет».
   Теперь ей нечего монтировать.
3. **Записать образ и сверить.** `dd … conv=fsync`, затем прочитать карту обратно и сравнить sha256 с образом. Скрипты
   для этого лежат на `anoir-pc`, см. ниже.

### Через сам Pi по USB (`rpiboot`) — с этого ПК не работает, не повторять

- **Почему вообще так можно.** Без загрузчика на карте Pi сам уходит в загрузку по USB: появляется устройство
  `0a5c:2763` «BCM2708 Boot». `rpiboot` (из `raspberrypi/usbboot`, собран без root, запускается через `pkexec`) отдаёт
  ему файлы.
- **Готовая прошивка `msd` для Zero.** Должна сделать из Pi флешку. Загружается, но как диск не появляется.
- **Стандартный `start.elf`.** Принимает по USB только файлы короче 64 байт; на остальных тайм-аут (`libusb` −7).
  Поэтому ядро загружается без `initrd`.
- **Обход: `boot_ramdisk=1`.** Ядро, `initrd` и всё остальное упаковано в один FAT-образ `boot.img`; его загружает ещё
  `bootcode.bin`, а там передача работает.
  - **Проверено.** Работал образ на 48 МБ; образы на 64 МБ и на 40 МБ, собранные заново, зависали. Причина не выяснена,
    рабочий путь — дописывать файлы в уже работавший образ.
  - **Ловушка `initramfs`.** Свой `cpio` можно дописать к стоковому `initramfs` только после выравнивания нулями до
    кратного 4 байтам, иначе ядро молча отбрасывает хвост.
- **Linux на Pi.** Загружается и карту видит (`mmcblk0`). Но режим USB-флешки (`dwc2` + `g_mass_storage`) до ПК так
  ни разу и не дошёл.
- **Последняя попытка — прошивка через Wi-Fi.** Linux по USB с драйвером Wi-Fi (`brcmfmac`, прошивка `43430`,
  `wpa_supplicant` с библиотеками) должен был сам скачать образ. До сети не дошёл: Pi не подключался к домашнему
  Wi-Fi (код 5 на диоде, см. ниже).
- **Диод как диагностика.** Это пригодилось. `init` моргал номером шага: 1 — старт, 2 — карта видна, 3 — драйвер
  Wi-Fi, 4 — адаптер, 5 — `wpa_supplicant`, 6 — подключился, 7 — получил адрес. «Сердцебиение» значило, что карты нет.

## Что выяснили про карты

- **Первая карта мёртвая.** Pi её не видит: и загрузчик, и Linux без `mmcblk0`, в том числе после чистки контактов.
  PocketBook её тоже не показал. Данные с неё снять не удалось.
- **Вторая карта поддельная.** Сообщает ровно 15 728 640 секторов, это 7,5 ГиБ (у настоящих карт на 8 ГБ объём
  «кривой», около 7,4 ГиБ). Всё, что записано дальше 121,875 МиБ, читается обратно нулями. Первые 64 МиБ хранятся
  правильно, поэтому подделка не видна, пока не проверишь всю карту. Такую карту вернуть продавцу.
- **Какую брать.** SanDisk Ultra A1 на 16–64 ГБ или Samsung EVO, у официального продавца. Безымянные (FRSONE,
  LuxVoice, «Micro SD 32 Гб») не брать. Проверка новой карты — записать образ и сверить sha256 всего образа, как выше.

## Что дальше, по шагам

1. **Купить настоящую microSD.**
2. **Записать образ через PocketBook** по порядку выше и сверить sha256. Образ уже с правильным регистром имени сети.
3. **Поставить Pi на зарядку у терминала**, через порт PWR IN. Первый запуск с cloud-init на Zero идёт несколько минут.
4. **Найти Pi в сети** (MAC `b8:27:eb`) и зайти: `ssh anoir@<адрес>`. Если не появился, проверить уровень сигнала
   Wi-Fi там, где он стоит. Запасной вариант — USB-кабель от среднего порта к ПК и SSH через USB-сеть.
5. **Поставить Tailscale и объявить exit node** — команды в [05-egress.md, «Как поднять»](../05-egress.md#как-поднять).
   Заодно: IP forwarding, журнал в память (`Storage=volatile`, меньше записи на карту), энергосбережение Wi-Fi выключить
   (`wifi.powersave = 2` в NetworkManager), сторожевой таймер systemd (`RuntimeWatchdogSec`), автообновление Tailscale.
6. **Админка Tailscale** — это делает владелец: одобрить узел и exit node, отключить срок ключа.
7. **Замер с сервера** по инструкции из 05-egress.md, с автоматическим откатом. Скорость вверх должна быть заметно
   выше 8 Мбит/с.
8. **Переключить сервер.** В `/opt/meatsuit/docker/.env` в `TS_EXTRA_ARGS` сменить имя узла с `anoir-pc` на
   `home-exit` и перезапустить контейнер Tailscale. После этого пересоздать сервис `apply` у cvs
   (`--force-recreate apply`): он живёт в сети браузера.
