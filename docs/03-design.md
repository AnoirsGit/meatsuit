# Как устроено и как пользоваться

Интерфейс и устройство частей — в [04-http-api.md](04-http-api.md). Здесь схема, решения и открытые вопросы.

## Схема

```
  я (телефон, ноутбук)                    проекты: cvs, tinder-matcher, …
          │ WebRTC, по tailnet                    │ HTTP: GET /view, POST /act
          ▼                                       ▼
 ┌────────────── сервер (Нидерланды), Docker ───────────────────┐
 │  Neko: Brave с постоянным профилем  ◄── CDP (только внутри) ──┤
 │        /data/profile                    meatsuit: очередь,    │
 │                                         руки, лимиты, guard   │
 │  всё в сетевом окружении контейнера Tailscale                 │
 └──────────────────────────┬────────────────────────────────────┘
                            │ весь трафик браузера, через exit node
                            ▼
              дом в Алматы: всегда включённое устройство
                            │
                            ▼
                    интернет, IP провайдера из Алматы
```

**Браузер один.** Neko показывает его мне, а те же страницы обслуживают ботов через meatsuit. Порт CDP наружу не торчит. Сервер стоит в датацентре, поэтому выход в сеть идёт через дом: IP подделать нельзя, подробности в [04-http-api.md](04-http-api.md#выход-в-сеть-алматы).

## Части

| Часть | Что делает |
|---|---|
| `docker/` | Tailscale с exit node, Neko с Brave, том с профилем, meatsuit |
| `server.js` | два входа: `GET /view`, `POST /act` |
| `driver.js`, `view.js` | Patchright `connectOverCDP`; видимый HTML с номерами (**есть**, проверено вживую на Chromium) |
| `human.js`, `human/` | мышь, прокрутка, ввод (уже есть) |
| `queue.js`, `limits.js` | один бот за раз, ритм и лимиты площадок |
| `guard.js`, `notify.js` | капча, вход, подозрительная страница: стоп и сообщение в Telegram. `guard.js` (распознавание) есть, `notify.js` нет |
| `egress.js` | проверка, что выход в сеть из Алматы |
| `life.js`, `life/` | фоновая «жизнь» (есть как отдельная команда, см. [06-warmup.md](06-warmup.md)) |

## Как пользоваться

### Мне

- Открываю зеркало Neko (только по tailnet) и живу в браузере как обычно.
- Нужен новый вход: вхожу там руками, больше ничего делать не надо.
- Бот застрял на капче: приходит сообщение в Telegram, окно бота остаётся открытым, я решаю капчу в зеркале.

### Проекту

```sh
H="Authorization: Bearer $MEATSUIT_TOKEN"
T=$(curl -s -H "$H" -d '{"do":"begin","task":"cvs:hh-apply","site":"hh.kz"}' $MEATSUIT/act | jq -r .task)
curl -s -H "$H" -H "X-Task: $T" -d '{"do":"goto","url":"https://hh.kz/vacancy/1"}' $MEATSUIT/act
curl -s -H "$H" -H "X-Task: $T" $MEATSUIT/view                     # видимый HTML
curl -s -H "$H" -H "X-Task: $T" -d '{"do":"click","target":"Откликнуться"}' $MEATSUIT/act
curl -s -H "$H" -H "X-Task: $T" -d '{"do":"end"}' $MEATSUIT/act
```

Что делает `begin`:
1. Встаёт в очередь. Пока выполняется чужая задача, ждёт.
2. Проверяет выход в сеть. Не Алматы — отказ, браузер не трогается.
3. Проверяет лимит площадки на сейчас. Исчерпан — отказ, в браузер не заходит.
4. Открывает **отдельное окно**, мои вкладки не трогает, `end` закрывает его.

После каждого действия проверяется `guard`: капча или страница входа — `409 needs_human`, проект откладывает задачу. Всё пишется в журнал: кто, где, когда и чем закончил.

Ритм и лимиты задаются в `sites.json`, а не в коде проекта (часы по Алматы):

```json
{ "hh.kz":        { "perDay": 15, "perHour": 3, "hours": "10-21" },
  "linkedin.com": { "perDay": 0 },
  "greenhouse.io":{ "perDay": 25, "perHour": 4, "hours": "9-22" } }
```

`perDay: 0` значит, что бот на этой площадке ничего не делает. LinkedIn пока стоит так: там риск выше, а терять сеть контактов нельзя.

### Руки: что умеет `human`

| Действие | Как ведёт себя |
|---|---|
| `click` | ищет по номеру, тексту кнопки, ссылки или подписи. К элементу за экраном крутит колесом, а не прыгает. Мышь идёт по слегка изогнутой кривой со своей скоростью у каждого движения: время по закону Фиттса, скорость колоколом, дрожь руки. На длинном пути иногда перелетает или не доезжает и доводит. Кликает около центра, не строго в него, перед нажатием задерживается, кнопку держит 45–200 мс |
| `fill` | клик в поле, потом ввод |
| `type` | настоящими клавишами, а не вставкой текста. Интервалы неровные, руки чередуются быстрее, чем один палец подряд, пауза после запятой и в начале предложения, иногда задумывается. Заглавные: Shift нажимает рука, противоположная клавише. Раскладки US и ЙЦУКЕН с настоящими `key` и `code`. Опечатки на соседних клавишах, замечает не сразу, стирает Backspace и перепечатывает; итог в поле всегда равен заказанному тексту. Темп (`wpm`) у каждой страницы свой и постоянный |
| `scroll` | колесом пачками рывков по 100, между ними пауза «прочитать», изредка шаг назад |
| `pause` | случайная пауза |

Планы (что и когда нажать) считают `human/mouse.js` и `human/keys.js` чистыми функциями, поэтому тесты воспроизводимы; `human.js` проигрывает их на странице по часам.

Позже, может быть, поиск кнопки моделью, когда текст не нашёлся, как в Stagehand.

## Решения

| Решение | Почему |
|---|---|
| Один браузер для всех, а не по профилю на проект | живой человек — лучший прогрев. Площадки и так знают, что это один я |
| HTTP вместо библиотеки | проекты на разных языках и в разных контейнерах, подключиться можно даже `curl` |
| Neko, а не noVNC | WebRTC: видео со звуком, кино смотреть можно |
| Patchright `connectOverCDP` за интерфейсом `Driver` | API Playwright без служебных команд DevTools; ввод уровня ОС делил бы со мной один курсор |
| Выход через домашний exit node | IP подделать нельзя; датацентр в Нидерландах выдал бы бота, домашний IP в Алматы совпадает с тем, с которого я и так сижу |
| Нет сети вместо запасного выхода | один выход через IP сервера хуже, чем простой |
| Отдельное окно на задачу | бот не трогает мои вкладки, и я вижу, что он делает |
| Капча означает стоп, а не обход | обход — гонка вооружений и прямой путь к бану |
| Без подмены отпечатков и геолокации | настоящий браузер согласован сам с собой, подмена даёт расхождение с IP |

## Что проверено на настоящем браузере

05.10.2026. Кроме 79 тестов (`node --test`, на фальшивой странице с виртуальными часами) руки и прогрев прогнаны на настоящем **Chromium** через Patchright, на локальных тестовых сайтах. Сквозные тесты на нём лежат в `test/e2e.test.js` и запускаются отдельно: `npm run test:e2e` (нужны Chromium и Patchright, около полутора минут; обычный `node --test` файл пропускает).

| Что | Результат |
|---|---|
| Печать смешанного текста (кириллица, заглавные, знаки русской раскладки, №) | текст точно попал в поле, все события `trusted` |
| Клик по элементу за экраном | страница прокручена колесом по 100 (27 рывков), а не прыжком |
| События мыши | координаты целые, ритм около 8 мс, подёргивания видны в записи пути (мера «грубости» пути 1.69 → 1.75) |
| Автопрогрев (`life.js`) | сессии с переходом по ссылкам (относительный `href`), возвратом вверх за ссылками, просмотром страницы с видео, остановкой на странице-блоке; пауза 24 ч записывается в `data/life.json` |

**Найдено и исправлено именно настоящим браузером** (тесты на фальшивой странице всё это пропускали):
- ссылка искалась по абсолютному `href`, а в разметке он относительный: теперь по значению атрибута;
- гонка «Execution context was destroyed» сразу после клика по ссылке;
- ссылки брались только из видимой части экрана: теперь, если их там нет, возвращается вверх ступенчато;
- случайный ритм событий мыши 7–17 мс был слишком неровным: теперь около 8 мс, как у мыши с опросом 125 Гц.

**Не проверено:**
- Brave через `connectOverCDP` (проверялся Chromium);
- сайты-детекторы;
- реальные сайты: hh, Tinder, YouTube, Хабр;
- сервер, exit node, WebRTC-зеркало (Neko);
- `life.js run` по расписанию в живую на протяжении суток и больше.

Допущение, зачем нужен прогрев, и его границы — [06-warmup.md](06-warmup.md).

## Открытые вопросы

1. **IP.** Решено: exit node на домашнем устройстве, [04-http-api.md](04-http-api.md#выход-в-сеть-алматы). Остаётся: какое устройство (роутер провайдера, скорее всего оптический терминал Huawei, Tailscale не поддерживает, нужна отдельная железка за ним: Raspberry Pi, мини-ПК или старый ноутбук) и не стоит ли дом за CGNAT (тогда туннель идёт через ретранслятор Tailscale, скорость ниже).
2. **Я и бот одновременно.** Brave один. Если я смотрю кино, а бот работает в своём окне, не притормозит ли браузер фоновое окно и что покажет `document.visibilityState` у страницы бота. Проверяется спайком. **Частично проверено:** Chromium под Patchright есть, события приходят как `trusted` ([выше](#что-проверено-на-настоящем-браузере)). Не проверено: Brave, фоновое окно рядом с моим видео, `visibilityState`.
3. **Patchright через `connectOverCDP`.** README Patchright про подключение к запущенному браузеру молчит. Заплатки остаются в силе при подключении или только при своём запуске? Проверить на сайтах-детекторах. **Частично проверено:** Chromium есть. Не проверено: Brave через `connectOverCDP`, сайты-детекторы, а значит и сам вопрос про заплатки.
4. **Brave в Neko.** **Решено 05.10.2026.** Образ `ghcr.io/m1k1o/neko/brave:3.1.6`; флаги браузера подаются заменой `/etc/neko/supervisord/brave.conf` и скриптом запуска (`docker/neko/`), порт CDP 9222 слушает внутри контейнера, остальные контейнеры делят с Neko сеть; профиль в томе. Проверено локально: зеркало работает, профиль переживает остановку и пересоздание. Для этого пришлось исправить три вещи (cookie «очищать при закрытии» в профиле образа, обёртка `brave-browser` проглатывала сигнал остановки, управление в Neko по умолчанию надо просить), см. [docker/README.md](../docker/README.md).
5. **Перенос входов.** Старый профиль браузера (раньше назывался `~/.apply-profile`; на этой машине его нет, где он сейчас, не проверено) переносить или войти заново через зеркало? Скорее заново: новое устройство и так новое.
6. **Neko в сети Tailscale-контейнера.** Не проверено (локально нет Tailscale; `docker-compose.egress.yml` валиден, запуск не проверялся). Нормально ли отдаёт WebRTC, находит ли зеркало по tailnet, идёт ли DNS через туннель, работает ли правило «браузеру нельзя наружу мимо туннеля».
7. **Как узнать, что я сейчас в зеркале.** Нужно, чтобы фоновая «жизнь» не стартовала при мне. В документации Neko есть статус управления; смотрит ли он, кто просто подключён, проверить. Пока не сделано: `life.js` запускается вручную и про зеркало ничего не знает ([06-warmup.md](06-warmup.md#риски-и-что-проверить-в-первую-очередь)).
8. **Язык.** tinder-matcher ищет кнопки по английскому тексту, hh отвечает по-русски. Браузер один, значит язык интерфейса один (`en-US,ru`), а русские надписи ищутся по номеру или по тексту.
9. **Геолокация.** Tinder просит позицию. Brave по умолчанию отключает сервис местоположения Google, и `navigator.geolocation` может не отдавать позицию; проверить, что отдаёт браузер за туннелем и что делает Tinder при отказе. Подмену (`setGeolocation`, как сейчас в tinder-matcher/common.js) не делаем.
10. **Длинные тексты.** Живой человек вставляет сопроводительное письмо из буфера, а не набирает 1500 знаков пять минут. Нужно действие `paste` (текст в буфер и Ctrl+V) и порог «печатать или вставить».
