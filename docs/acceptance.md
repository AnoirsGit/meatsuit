# Живая проверка зеркала (приёмка)

Тесты (`npm test`) гоняют библиотеку на подставных страницах и проверяют файлы Docker без запуска. Обещание
«вход один раз, дальше браузер помнит» и работу библиотеки с настоящим зеркалом проверяет только эта процедура.
Её проходят руками на сервере (или на своей машине) после каждой смены браузера, образа или compose и записывают
результат в таблицу в конце файла.

Что доказывает, по шагам: зеркало поднято → вход на сайт руками один раз → перезапуск и пересоздание контейнера →
сессия жива → dryRun-задача из библиотеки в соседнем контейнере (так подключаются вызывающие) → окно задачи
закрылось → страница входа даёт `NeedsHuman` и окно остаётся человеку.

Чего не доказывает: звук и видео на телефоне, выход через Tailscale (своя проверка — [egress.md](egress.md#verify)),
как площадки относятся к автоматизации.

В записях и в этом файле — никаких адресов, имён машин, логинов и паролей.

## Подготовка

Нужны Docker с Compose 2.24 или новее и Node 20+ на сервере.

```sh
git clone <адрес репозитория> meatsuit && cd meatsuit
npm ci                     # playwright-core для tools/live-check.js
npm run init               # файл деплоя (или MEATSUIT_CONFIG=<файл> npm run init), повторный запуск ничего не трогает
npm run config -- --tailnet   # страница правки: NEKO_BIND_IP и NEKO_WEBRTC_IP — адрес tailnet сервера, MEATSUIT_BROWSER, MEATSUIT_TZ
git rev-parse --short HEAD # коммит — в запись результата
```

Если файл деплоя лежит не в `docker/.env`, задайте `export MEATSUIT_CONFIG=<файл>` на всё время проверки: его
читают `docker/up.sh` и `docker/verify.sh`.

## 1. Зеркало поднято

```sh
docker/up.sh               # docker compose --env-file <файл> up -d
docker/up.sh ps -a         # neko — healthy (до 2 минут), profile-init — exited (0)
docker/verify.sh           # в конце «ВСЁ В ПОРЯДКЕ»
```

Откройте `http://<адрес>:<NEKO_PORT>` в обычном браузере, имя любое, пароль участника из файла деплоя. Наведите
мышь на видео — управление ваше. Наберите адрес в адресной строке и нажмите Enter с настоящей клавиатуры
(это ещё ни разу не проверялось, см. [docker/README.md](../docker/README.md#what-was-verified-and-what-was-not)).

**Записать:** браузер (`MEATSUIT_BROWSER`), тег образа (`NEKO_TAG`), healthy да/нет, `verify.sh` OK/FAIL, Enter
с клавиатуры да/нет.

## 2. Вход руками, один раз

В зеркале войдите на свою площадку (любой свой аккаунт). Если площадка спросит код или капчу — решите их там же.

**Записать:** на какой площадке вошли (только имя площадки).

## 3. Сессия переживает перезапуск и пересоздание

```sh
docker/up.sh restart neko                       # тот же контейнер
docker/up.sh up -d --force-recreate neko        # новый контейнер, тот же том профиля и то же имя хоста
docker/verify.sh persistence                    # cookie, поставленная прямо перед остановкой, на месте
```

После каждой из двух команд дождитесь `healthy` (`docker/up.sh ps`) и откройте площадку в зеркале: вы должны быть
внутри, без входа. Окна «профиль используется на другом компьютере» быть не должно.

**Записать:** после `restart` — вход жив да/нет; после `--force-recreate` — вход жив да/нет, окно «профиль занят»
было/не было; `verify.sh persistence` OK/FAIL.

## 4. dryRun-задача из библиотеки в соседнем контейнере

Так к браузеру подключаются вызывающие: контейнер в сети браузера, CDP на `127.0.0.1:9222`. Проверка — две
dryRun-задачи на `example.com` (зарезервированный домен), ничего не нажимается, слоты лимитов не тратятся.

```sh
docker run --rm --network container:meatsuit-browser --user 1000:1000 \
  -v "$PWD":/app:ro -v meatsuit_profile:/meatsuit -w /app node:22-slim \
  node tools/live-check.js --cdp http://127.0.0.1:9222 --dir /meatsuit/state
```

`--dir` — та же папка `state/` в томе `meatsuit_profile`, что у вызывающих: замок очереди общий, и проверка не
войдёт в браузер одновременно с ботом. Задачи `live-check` попадут в их журнал `journal.jsonl` с пометкой dryRun.

Ожидается четыре строки `OK`:

```
OK   dryRun-задача открыла площадку и вернула снимок — https://example.com/ «Example Domain», элементов: …
OK   окно задачи закрыто — окон до: N, после: N
OK   страница входа остановила задачу (NeedsHuman) — страница входа, https://example.com/login
OK   окно после NeedsHuman осталось человеку — https://example.com/login: закройте его в зеркале
```

В зеркале в это время видно, как открывается и закрывается окно задачи, а окно с `/login` остаётся. Закройте его
руками. Код выхода: 0 — всё OK, 1 — есть `FAIL`.

**Записать:** четыре строки как есть (адресов в них нет) и код выхода.

### С другой машины (по желанию)

CDP наружу не публикуется. Чтобы запустить ту же проверку с ноутбука, на время проверки поднимите на сервере
пересылку внутри сети браузера и пробросьте её по SSH (без Tailscale-выхода: при `MEATSUIT_EGRESS=tailscale` у
браузера нет своего адреса в сети Docker):

```sh
# на сервере
docker run -d --rm --name meatsuit-cdp-forward --network container:meatsuit-browser node:22-slim \
  node -e "const n=require('net');n.createServer(c=>{const u=n.connect(9222,'127.0.0.1');c.pipe(u).pipe(c);c.on('error',()=>u.destroy());u.on('error',()=>c.destroy())}).listen(9223)"
docker inspect -f '{{range .NetworkSettings.Networks}}{{.IPAddress}}{{end}}' meatsuit-browser   # адрес контейнера

# на ноутбуке, в клоне репозитория после npm ci
ssh -N -L 9222:<адрес контейнера>:9223 user@server &
node tools/live-check.js --cdp http://127.0.0.1:9222 --dir ~/.meatsuit-live-check

# после проверки — обязательно
docker stop meatsuit-cdp-forward       # на сервере
kill %1                                # на ноутбуке: SSH-туннель
```

`--dir` на ноутбуке — не тот же, что у ботов на сервере: замок очереди не общий, поэтому так проверяйте только когда
боты не работают.

## Запись результата

Одна строка на прогон. Ячейки — да/нет, OK/FAIL и коды; без адресов, имён машин и логинов.

| Дата | Коммит | Браузер, тег | 1. healthy, verify, Enter | 2. площадка | 3. restart, recreate, «профиль занят», persistence | 4. live-check (код) | Кто |
|---|---|---|---|---|---|---|---|
| 2026-10-08 | ветка ms-trunk (до переписи истории) | chrome, 3.1.6 | да, OK, не проверялось (без человека) | — (без аккаунта) | healthy, healthy, не было, OK (вход не проверялся) | 4×OK (0) | агент, локально на ноутбуке |

Строка выше — локальная репетиция без аккаунта: шаг 2 и «вход жив» из шага 3 там не проверены, Enter с настоящей
клавиатуры — тоже. С 08.10.2026 compose работает на сервере (`verify.sh` и `persistence` зелёные, вход вызывающего
держится), но строку прогона сервера сюда ещё не записали — пункт 2 в [ROADMAP.md](ROADMAP.md).
