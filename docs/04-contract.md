# Контракт: проект ↔ meatsuit

meatsuit — руки и глаза. Он показывает страницу и выполняет команды. Решает проект (модель), meatsuit ничего не решает.

Подключение: `const { connect } = require('meatsuit')`. Код — CommonJS, Node 18+.

## connect и task

```js
const ms = await connect({ cdpUrl, dir?, sitesFile?, notify? });
const result = await ms.task(name, async ({ see, act }) => { ...; return value; },
                             { site, maxCommands = 60, maxMinutes = 10, dryRun = false });
await ms.close();
```

| Параметр | Смысл |
|---|---|
| `cdpUrl` | адрес CDP общего браузера |
| `dir` | где замок очереди, счётчики лимитов, журнал (по умолчанию `~/.meatsuit`) |
| `sitesFile` | лимиты площадок (по умолчанию `sites.json` в meatsuit); `maxCommands` и `maxMinutes` в нём — потолок, ниже которого проект выбирать может, а выше нет |
| `notify(text, event)` | асинхронная функция уведомлений; `telegramNotifier({token, chatId, threadId?})` — готовая, шлёт в группу или тему форума. Сбой отправки задачу не роняет, пишется в stderr без токена |
| `notifyOn` | какие события слать: `'start'`, `'done'`, `'limit'`, `'error'`, `'needsHuman'`; по умолчанию `['needsHuman','limit','error']`, чтобы по каждому матчу не засыпать группу |
| `site` | хост, например `tinder.com`; им же ограничивается `goto` |

`task` по порядку: встаёт в очередь (один бот за раз) → проверяет лимит площадки и записывает задачу → открывает отдельное окно → зовёт функцию → закрывает окно. Возвращает то, что вернула функция.

Ошибки (все классы экспортируются из `meatsuit`):

| Ошибка | Когда | Что делать проекту |
|---|---|---|
| `LimitReached` | площадки нет в `sites.json`, `perDay: 0`, вне часов, лимит дня или часа | задачу не начинать, повторить позже |
| `NeedsHuman` (`.reason`, `.url`) | капча, страница входа, блокировка | остановиться, задачу отложить; окно осталось открытым, человек решает руками |
| `BudgetExceeded` | больше `maxCommands` команд или `maxMinutes` минут | считать задачу неудачной |
| `StaleElement` | `gen` команды не совпал с текущим снимком, элемента нет или содержимое узла изменилось после снимка | взять свежий снимок и выбрать заново |
| `BadCommand` | команда не из набора или с плохими полями | ошибка вызывающего кода или модели |

## Глаза: `see(opts?)`

```js
const snap = await see();                     // полный снимок
const snap = await see({ screenshot: true }); // + JPEG q60 в base64, поле screenshot
const d    = await see({ since: prevSnap });  // только изменения (см. ниже)
```

Снимок:

```js
{ gen: 4,                       // поколение, обязательно в командах
  url, title,
  text: '…',                    // видимый текст в порядке чтения, до 6000 символов
  elements: [                   // видимые и не перекрытые интерактивные элементы
    { id: 1, role: 'button'|'link'|'textbox'|'checkbox'|'radio'|'select'|'tab'|…,
      name: 'Like',             // подпись, до 80 символов
      inView: true,             // в окне просмотра сейчас (false — нужно прокрутить)
      value?, checked?, disabled?, focused?, selected?,
      href?,                    // у ссылок: атрибут href как есть, до 200 символов
      inputType?: 'password' } ],   // у пароля value не отдаётся никогда
  dialogs: [ { name, text, elements: [id, …] } ],   // модалки и попапы
  frames: [url, …],             // адреса чужих iframe (капча и т.п.)
  screenshot? }
```

Номера `id` действуют только внутри своего `gen`. После любой команды страница получает новый `gen` и новую нумерацию.

`see({ since })` и результат `act` — diff:

```js
{ gen, url, title, urlChanged, changed,
  elements,                     // полный новый список, нумерация новая
  added: [element], removed: [{ role, name }],
  text?, dialogs?, screenshot? } // text и dialogs только если изменились
```

## Руки: `act(command)`

Набор закрытый. Любая другая команда — `BadCommand` до выполнения.

| Команда | Поля | Примечание |
|---|---|---|
| `click` | `id`, `gen` | прокрутка к элементу, мышь по кривой в случайном темпе (быстрый бросок за ~1 с с перелётом и дёрганым возвратом, обычный, медленный), клик в случайную точку; курсор уже над элементом — мышь не двигается. Подробнее в `03-design.md` |
| `fill` | `id`, `gen`, `text` | клик, очистка поля, ввод с опечатками; `text` до 1000 символов, **одна строка** (перевод строки нажал бы Enter и отправил полсообщения) |
| `type` | `text` | ввод в сфокусированное поле, одна строка |
| `press` | `key` | `Enter` `Escape` `Tab` `Backspace` `ArrowDown` `ArrowUp` `PageDown` `PageUp` |
| `scroll` | `px?` | колесом рывками вниз, от 0 до 5000 |
| `wait` | `ms` (до 15000) или `text` | ждёт паузу или появления текста |
| `back` | — | назад по истории |
| `goto` | `url` | только `https:` и только хост площадки (`site`) или его поддомен |

Возвращает diff снимка после команды. Команды и снимки выполняются строго по очереди. Результат `see()`/`act()` проходит через `guard`: при капче (в том числе в iframe), входе, блокировке или если страница ушла с хоста площадки, вместо результата бросается `NeedsHuman`. Это состояние не снимается: все следующие `see`/`act` в этой задаче бросают ту же ошибку, даже если проект её поймал, а `task` в конце тоже завершится `NeedsHuman`. Новые вкладки, открытые страницей (`target=_blank`, `window.open`), закрываются.

`dryRun: true`: `see` работает, `act` ничего не делает, возвращает `{ dryRun: true, changed: false }` (это не снимок: поля `url` нет) и пишет в журнал. Исключение: `goto` выполняется и возвращает diff, как обычно (журнал: `result: 'ok'`, `dryRun: true`): навигация только читает страницу, а без неё окно задачи остаётся `about:blank` и проекту нечего видеть. Все остальные команды (`click`, `fill`, `type`, `press`, `scroll`, `wait`, `back`) в dryRun не выполняются.

## Журнал

`<dir>/journal.jsonl`, по строке на команду: `ts`, `dryRun`, `cmd`, `url`, `result: 'ok'|'dry-run'` или `error`, `urlAfter`.

## Запись и воспроизведение (для отладки без браузера)

```js
const { hands, replay } = require('meatsuit');
hands(page, { recordDir })   // пишет снимки в NNNN.json (первый см. + результаты команд)
replay(recordDir)            // тот же интерфейс { see, act } без браузера
```

`replay.act` проверяет команду как настоящую (в том числе `gen` и наличие `id`), двигает запись на один снимок вперёд и бросает «запись закончилась», когда снимки кончились. Это даёт тестировать цикл бота на сохранённых страницах.

## Чего meatsuit не делает

- не решает, что нажимать, и не пишет тексты;
- не выполняет произвольный JS и не переходит на чужие хосты;
- не обходит капчу: на ней стоп и сообщение человеку;
- не подменяет отпечатки браузера.

## Обязанности проекта

- Использовать только последний `gen`; после `act` брать `gen` и `elements` из ответа.
- Проверять ответ модели до `act`: команда из набора, `id` есть в снимке, текст не пустой.
- Не класть в журнал и в модель лишние данные чужих профилей.
- Первый запуск на живой площадке — только `dryRun`.

## Telegram

Адаптер `telegram.js` (экспортируется из `meatsuit`): `createTelegram({ token, chatId, threadId?, apiBase? })` → `send(text, { silent?, parseMode?, threadId? })`.
- Длинный текст режется на сообщения до 4096 символов по концам строк.
- 429: ждёт `retry_after` (не дольше 30 с), до трёх повторов; 5xx: один повтор; остальные 4xx сразу ошибка с подсказкой (неверный токен, бота удалили из группы, неверный chatId).
- Группа стала супергруппой: берёт новый `chat_id` из ответа и предупреждает, что конфиг надо обновить.
- Токен не попадает в тексты ошибок.
- `findChats({ token })` и `node telegram.js chats`: показать группы и темы, которые бот видел (чтобы узнать chatId). Не работает, если у бота включён webhook; в группе бот видит обычные сообщения, только если у него выключен privacy mode (BotFather → `/setprivacy`) или он админ, а факт добавления в группу виден всегда.
