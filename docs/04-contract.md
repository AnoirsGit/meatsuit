# Контракт: проект ↔ meatsuit

meatsuit — руки и глаза. Он показывает страницу и выполняет команды. Решает проект (модель), meatsuit ничего не решает.

Подключение: `const { connect } = require('meatsuit')`. Код — CommonJS, Node 18+.

## connect и task

```js
const ms = await connect({ cdpUrl, dir?, sitesFile?, notify? });
const result = await ms.task(name, async ({ see, act }) => { ...; return value; },
                             { site, maxCommands = 60, maxMinutes = 10, dryRun = false, dryRunNavigation = false, readOnly = false, capture? });
await ms.close();
```

| Параметр | Смысл |
|---|---|
| `cdpUrl` | адрес CDP общего браузера |
| `dir` | где замок очереди, счётчики лимитов, журнал (по умолчанию `~/.meatsuit`) |
| `sitesFile` | лимиты площадок (по умолчанию `sites.json` в meatsuit); `maxCommands` и `maxMinutes` в нём — потолок, ниже которого проект выбирать может, а выше нет; `singleTab: true` — режим одной вкладки (см. ниже); необязательный ключ `"*"` — правило для хостов, которых в файле нет (см. «Правило по умолчанию») |
| `notify(text, event)` | асинхронная функция уведомлений; `telegramNotifier({token, chatId, threadId?})` — готовая, шлёт в группу или тему форума. Сбой отправки задачу не роняет, пишется в stderr без токена |
| `notifyOn` | какие события слать: `'start'`, `'done'`, `'limit'`, `'error'`, `'needsHuman'`; по умолчанию `['needsHuman','limit','error']`, чтобы по каждому матчу не засыпать группу |
| `capture` | архив экранов, см. «Архив экранов»: `{ dir, htmlPerSignature = 5, maxMB = 500 }`; без него ничего не пишется |
| `site` | хост, например `tinder.com`; им же ограничивается `goto` |
| `readOnly` | по умолчанию `false`. Задача, которая только читает: тратит `perHour`, а `perDay` не тратит и им не останавливается (часы работы и `perDay: 0` действуют как всегда). Если внутри выполнена команда записи (`fill`, `type`, `press` Enter, `click` не по элементу с ролью `tab` из последнего снимка), полный слот дня засчитывается ДО выполнения первой такой команды, один раз за задачу; если дневной лимит уже исчерпан, команда не выполняется и приходит `LimitReached`. Без флага слот полный сразу, как раньше. `dryRun` слотов не тратит в любом случае |

`task` по порядку: встаёт в очередь (один бот за раз) → проверяет лимит площадки и записывает задачу → открывает отдельное окно → зовёт функцию → закрывает окно. Возвращает то, что вернула функция.

**Правило по умолчанию.** Правило площадки ищется в `sites.json` по точному совпадению ключа с `site`. Необязательный ключ `"*"` — правило для хостов, которых в файле нет; это обычная запись со всеми полями (`perDay`, `perHour`, `hours`, потолки `maxCommands`/`maxMinutes`, `singleTab`). Счётчики при этом у каждого хоста свои: в `limits.json` ключ — сам хост, а не `"*"`. Явная запись заменяет `"*"` целиком и с ним не сливается: площадка с `"perDay": 0` остаётся закрытой при любом `"*"`, а запись без `hours` часов из `"*"` не получает. Без `"*"` неописанный хост даёт `LimitReached`, как раньше. Поддомен описанной площадки (`www.x.com` при описанном `x.com`) под `"*"` не попадает и запись `x.com` не наследует: это `LimitReached` «площадка не описана», с `"*"` и без него, так что закрытую площадку сменой `site` не обойти. Площадку нужно звать её ключом из файла (внутри задачи `goto` на её поддомены и так разрешён). `site: '*'` — не хост: `task` бросает ошибку, правило по умолчанию так не получить.

Площадка с `"singleTab": true` в `sites.json` (для площадок, которые держат одну активную вкладку и гасят прежнюю, когда открыта вторая) окно не открывает: задача идёт в уже открытой вкладке этой площадки (первая страница с хостом `site` или его поддомена), и вкладка после задачи не закрывается. Нет такой вкладки: открывается одна и остаётся; чтобы она нашлась в следующий раз, задача должна перейти на сайт (`goto`). Если вкладка на хосте есть, а Playwright её не видит (на Debian Chromium так было), `task` бросает ошибку, а не открывает дубль; вкладка ищется до траты слота лимита, окно открывается после. Если открытое задачей окно осталось не на площадке (задача упала до `goto`), оно закрывается, кроме остановки на NeedsHuman. Найденную вкладку задача берёт, только когда её снимок проходит guard (команды не выполняются, проверка идёт до траты слота); иначе `task` бросает NeedsHuman с уведомлением `needsHuman`, страница не тронута, слот не потрачен. Проверка идёт для любой найденной вкладки и ничего не помнит между задачами, поэтому не зависит от процесса: вкладку с капчей, оставленную человеку прошлым запуском (cron, новый процесс), следующий тоже не тронет. Без флага всё как раньше: окно на задачу.

Ошибки (все классы экспортируются из `meatsuit`):

| Ошибка | Когда | Что делать проекту |
|---|---|---|
| `LimitReached` | площадки нет в `sites.json` (и нет правила `"*"`), `perDay: 0`, вне часов, лимит дня или часа | задачу не начинать, повторить позже |
| `NeedsHuman` (`.reason`, `.url`) | капча, страница входа, блокировка | остановиться, задачу отложить; окно осталось открытым, человек решает руками |
| `BudgetExceeded` | больше `maxCommands` команд или `maxMinutes` минут | считать задачу неудачной |
| `StaleElement` | `gen` команды не совпал с текущим снимком, элемента нет или содержимое узла изменилось после снимка | взять свежий снимок и выбрать заново |
| `BadCommand` | команда не из набора или с плохими полями | ошибка вызывающего кода или модели |

## Глаза: `see(opts?)`

```js
const snap = await see();                     // полный снимок
const snap = await see({ screenshot: true }); // + JPEG q60 в base64, поле screenshot
const snap = await see({ settle: { minElements: 3, quietMs: 500, timeoutMs: 10000 } }); // ждать отрисовку SPA
const d    = await see({ since: prevSnap });  // только изменения (см. ниже)
```

`settle` (необязательно, все поля тоже): снимать повторно (раз в ~100 мс), пока набор элементов и текст не замрут на `quietMs` (500) и элементов не станет не меньше `minElements` (1); не дольше `timeoutMs` (10000, сверху ограничен 15000 как `wait`: `supervise` проверяет `maxMinutes` только перед вызовом, и без потолка `settle` обошёл бы срок задачи). По таймауту возвращается последний снимок, исключения нет, проверять результат должен проект. Без `settle` один снимок сразу, как раньше. Выбрана опция `see`, а не `wait until:'elements'`: в dryRun `wait` не выполняется, а `see` работает, и именно dryRun нужен для первого захода на живую площадку; к тому же `wait` стоит команды из бюджета `maxCommands`, а снимок нет. Каждый промежуточный снимок получает свой `gen`; в проект уходит последний. Совместимо с `since` и `screenshot` (картинка снимается один раз, в конце).

Снимок:

```js
{ gen: 4,                       // поколение, обязательно в командах
  url, title,
  text: '…',                    // видимый текст в порядке чтения, до 6000 символов
  textParts?: [n, …],           // длины кусков text (light DOM, потом каждый shadow-корень), только если корни дали текст
  elements: [                   // видимые и не перекрытые интерактивные элементы
    { id: 1, role: 'button'|'link'|'textbox'|'checkbox'|'radio'|'select'|'tab'|…,
      name: 'Like',             // подпись, до 80 символов
      inView: true,             // в окне просмотра сейчас (false — нужно прокрутить)
      value?, checked?, disabled?, focused?, selected?,
      href?,                    // у ссылок: атрибут href как есть, до 200 символов
      inputType?: 'password' } ],   // у пароля value не отдаётся никогда
  dialogs: [ { name, text, elements: [id, …] } ],   // модалки и попапы
  frames: [url, …],             // адреса чужих iframe (капча и т.п.)
  screenshot? }
```

Номера `id` действуют только внутри своего `gen`. После любой команды страница получает новый `gen` и новую нумерацию.

**Shadow DOM.** Снимок заходит в открытые (`mode: 'open'`) shadow-корни, в том числе вложенные: элементы из них нумеруются в порядке документа наравне с остальными, `click`/`fill` по ним работают как обычно, текст из корней добавляется в конец `text`, поэтому `guard` видит капчу и вход и там. Каждый корень — отдельный кусок, их длины лежат в `textParts` (поле есть, только если корни дали текст): порог короткой страницы `guard` (600 символов) применяет к light DOM и к каждому корню отдельно, иначе длинный баннер cookie в shadow прятал бы заглушку «Too many requests» из light DOM. Обратная сторона: короткий корень со словом «captcha» остановит задачу и на длинной странице. Из корней берётся только отрисованный текст, в том числе текстовые узлы прямо в корне (так рендерит Lit): `<style>`, `<script>`, `<template>`, узлы с `display:none` и корни скрытых хостов в `text` не попадают. Слоты учитываются: кнопка, чья подпись приходит через `<slot>` из light DOM, есть в снимке (подпись над ней не считается перекрытием), а её `name` собирается из назначенных слоту узлов; неотрисованные узлы (CSS, `display:none`, `visibility:hidden`) в `name` не попадают. Известное ограничение: закрытые (`mode: 'closed'`) корни недоступны, их содержимое в снимке отсутствует (и guard его не проверяет); iframe внутри shadow по-прежнему видны через `frames`.

`see({ since })` и результат `act` — diff:

```js
{ gen, url, title, urlChanged, changed,
  elements,                     // полный новый список, нумерация новая
  added: [element], removed: [{ role, name }],
  text?, textParts?, dialogs?, screenshot? } // text (с textParts) и dialogs только если изменились
```

## Руки: `act(command)`

Набор закрытый. Любая другая команда — `BadCommand` до выполнения.

| Команда | Поля | Примечание |
|---|---|---|
| `click` | `id`, `gen` | прокрутка к элементу, мышь по кривой в случайном темпе (быстрый бросок за ~1 с с перелётом и дёрганым возвратом, обычный, медленный), клик в случайную точку; курсор уже над элементом — мышь не двигается. Подробнее в `03-design.md` |
| `fill` | `id`, `gen`, `text` | клик, очистка поля, ввод с опечатками; `text` до 1000 символов, **одна строка** (перевод строки нажал бы Enter и отправил полсообщения) |
| `type` | `text` | ввод в сфокусированное поле, одна строка |
| `press` | `key` | `Enter` `Escape` `Tab` `Backspace` `ArrowDown` `ArrowUp` `PageDown` `PageUp` |
| `scroll` | `px?` | колесом рывками вниз, от 0 до 5000 |
| `wait` | `ms` (до 15000) или `text` | ждёт паузу или появления текста |
| `back` | — | назад по истории |
| `goto` | `url` | только `https:` и только хост площадки (`site`) или его поддомен |

Возвращает diff снимка после команды. Команды и снимки выполняются строго по очереди. Результат `see()`/`act()` проходит через `guard`: при капче (в том числе в iframe), входе, блокировке или если страница ушла с хоста площадки, вместо результата бросается `NeedsHuman`. Это состояние не снимается: все следующие `see`/`act` в этой задаче бросают ту же ошибку, даже если проект её поймал, а `task` в конце тоже завершится `NeedsHuman`. Новые вкладки, открытые страницей (`target=_blank`, `window.open`), закрываются.

`dryRun: true`: `see` работает, `act` ничего не делает, возвращает `{ dryRun: true, changed: false }` (это не снимок: поля `url` нет) и пишет в журнал. Исключение: `goto` выполняется и возвращает diff, как обычно (журнал: `result: 'ok'`, `dryRun: true`): навигация только читает страницу, а без неё окно задачи остаётся `about:blank` и проекту нечего видеть. Все остальные команды (`click`, `fill`, `type`, `press`, `scroll`, `wait`, `back`) в dryRun не выполняются. Узкое исключение, по умолчанию выключено: `task(..., { dryRun: true, dryRunNavigation: true })` (или `hands(page, { dryRunNavigation })`) выполняет `click` по элементу с ролью `tab` из последнего снимка (переключение вида внутри страницы): это чтение. Клик по `button`, `link`, `textbox` и т. д., `fill`, `type`, `press` по-прежнему только в журнал (`result: 'dry-run'`); клик по `tab` пишется как `result: 'ok'`, `dryRun: true`, возвращает diff. Опция нужна, потому что без неё поведение «в dryRun только `goto`» закреплено e2e-тестами проектов; клик по устаревшему `gen` или без `see()` в dryRun остаётся пустой записью в журнале. Клик идёт по координатам, а мышь движется до нескольких секунд: страница могла показать оверлей или сдвинуть вёрстку. Поэтому прямо перед нажатием в изолированном мире проверяется, что `document.elementFromPoint` в точке клика — целевой элемент или его потомок, причём между ними нет другого интерактивного элемента (тот же набор, что нумерует снимок: кнопка, ссылка, поле и т. п.; например «× закрыть чат» внутри вкладки); иначе `StaleElement`, клика нет. Проверка заходит в открытые shadow-корни и поднимается по составному дереву (слот, хост), поэтому вкладки внутри open shadow поддерживаются. Над вкладкой по тому же составному дереву тоже не должно быть ссылки, кнопки, поля или `<label>` (тот же набор плюс `label`): клик всплыл бы к ним и выполнил переход, отправку формы или переключение поля, хотя под курсором сама вкладка. Такой клик тоже отклоняется `StaleElement`; свежий снимок тут не поможет, эту вкладку в dryRun не нажать. Проверка включена только в dryRun (там единственная настоящая запись); в обычном режиме её нет. Риск: страница может навесить на `role=tab` не только переключение вида, поэтому включать только для проверенных площадок.

## Журнал

`<dir>/journal.jsonl`, по строке на команду: `ts`, `dryRun`, `cmd`, `url`, `result: 'ok'|'dry-run'` или `error`, `urlAfter`.

## Запись и воспроизведение (для отладки без браузера)

```js
const { hands, replay } = require('meatsuit');
hands(page, { recordDir })   // пишет снимки в NNNN.json (первый см. + результаты команд)
replay(recordDir)            // тот же интерфейс { see, act } без браузера
```

`replay.act` проверяет команду как настоящую (в том числе `gen` и наличие `id`), двигает запись на один снимок вперёд и бросает «запись закончилась», когда снимки кончились. Это даёт тестировать цикл бота на сохранённых страницах.

## Архив экранов (`capture`)

```js
ms.task(name, fn, { site, capture: { dir, htmlPerSignature: 5, maxMB: 500 } })   // или hands(page, { capture })
const { signature, normalizeName, urlPattern } = require('meatsuit');
```

На каждый снимок (`see()` и результат `act`, кроме dryRun-действий без снимка) пишется `<dir>/<YYYY-MM-DD>/<seq>.json`: `{ts, signature, shape, urlPattern, title, snapshot (без screenshot), cmd?, html?}`. Если для этой подписи сохранено меньше `htmlPerSignature` страниц, рядом лежит `<seq>.html` (`page.content()`, ничего в страницу не пишется); счётчики подписей хранятся в `<dir>/html-counts.json` и переживают перезапуски. Когда архив больше `maxMB`, удаляются самые старые папки дат (сегодняшняя остаётся). Сбой записи задачу не роняет, пишется в stderr.

Санитизация HTML до записи: тела `<script>` и `<style>` вырезаются, у `<input type=password|hidden>` убирается `value`, `data:`-URI длиннее 200 символов заменяются на `data:[вырезано]`.

`signature(snapshot)` → `{ hash, shape, urlPattern }`, чистая функция. Подпись зависит от шаблона адреса (id, числа и токены → `:id`), множества (роль, нормализованное имя, шаблон href) элементов с количеством, сглаженным до `1`, `2-5`, `6+` (список из 3 и из 4 матчей один экран, из 7 другой), состава диалогов и хостов frames; ещё различаются `disabled` у элемента и непустое поле ввода. Не влияют: люди (имя ссылки с id в адресе → `<имя>`), тексты, цифры в именах (→ `#`), имена длиннее 40 символов (→ `<текст>`). Имя человека в кнопке без id в адресе не распознаётся.

**Приватность:** на диске настоящие страницы с чужими именами, фото (адреса) и перепиской. Папку держать вне репозитория (проект кладёт её в `.gitignore`), не копировать и не выкладывать. Санитизация убирает секреты разметки, а не личные данные.

## Чего meatsuit не делает

- не решает, что нажимать, и не пишет тексты;
- не выполняет произвольный JS и не переходит на чужие хосты;
- не обходит капчу: на ней стоп и сообщение человеку;
- не подменяет отпечатки браузера.

## Обязанности проекта

- Использовать только последний `gen`; после `act` брать `gen` и `elements` из ответа.
- Проверять ответ модели до `act`: команда из набора, `id` есть в снимке, текст не пустой.
- Не класть в журнал и в модель лишние данные чужих профилей.
- Первый запуск на живой площадке — только `dryRun`.

## Telegram

Адаптер `telegram.js` (экспортируется из `meatsuit`): `createTelegram({ token, chatId, threadId?, apiBase? })` → `send(text, { silent?, parseMode?, threadId? })`.
- Длинный текст режется на сообщения до 4096 символов по концам строк.
- 429: ждёт `retry_after` (не дольше 30 с), до трёх повторов; 5xx: один повтор; остальные 4xx сразу ошибка с подсказкой (неверный токен, бота удалили из группы, неверный chatId).
- Группа стала супергруппой: берёт новый `chat_id` из ответа и предупреждает, что конфиг надо обновить.
- Токен не попадает в тексты ошибок.
- `findChats({ token })` и `node telegram.js chats`: показать группы и темы, которые бот видел (чтобы узнать chatId). Не работает, если у бота включён webhook; в группе бот видит обычные сообщения, только если у него выключен privacy mode (BotFather → `/setprivacy`) или он админ, а факт добавления в группу виден всегда.
