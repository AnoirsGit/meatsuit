# Контракт ядра: проект ↔ meatsuit

meatsuit — запуск браузера, запоминание и глаза с руками. Он показывает страницу и выполняет команды;
решает проект (модель), meatsuit ничего не решает. Учётные данные (токены, ключи, пароли сайтов) приносит
вызывающий в аргументах и колбэках: ядро не читает окружение и само никуда не шлёт.

Разделы описывают то, что есть в коде сейчас. Что не проверено и чего нет — в «Ограничения».
Английская версия — [contract.md](contract.md); меняются вместе.

## Что входит в ядро

| Где | Что |
|---|---|
| корень репозитория | библиотека: `index.js` (`connect`/`task`), `eyes.js` и `dom.js` (снимок), `hands.js` (команды), `human.js` и `human/` (мышь, колесо, клавиатура, повадки), `guard.js`, `supervise.js`, `limits.js`, `window.js`, `capture.js`, `telegram.js`; `sites.example.json`; тесты `npm test` |
| `tools/` | программы для человека: `init.js` и `config-ui.js` (файл деплоя), `live-check.js` (приёмка), `secret-scan.sh` и `hooks/`, `save-tab.js` (сохранить открытые вкладки в архив), `telegram-chats.js` (узнать chatId группы) |
| `docker/` | зеркало: браузер в Neko (Google Chrome по умолчанию или Brave), к нему подключаются по CDP; профиль живёт в томе ([docker/README.md](../docker/README.md)) |
| `extras/` | поддерживаемые сервисы вокруг ядра: HTTP-сервис (`GET /view`, `POST /act`), прогрев (`life*`), проверка выхода (`egress`), очередь, `notify`, хозяин у руля, замок браузера и `selfcheck`. Развиваются и тестируются (`npm --prefix extras ci`, затем `npm run test:extras`). Ядро из `extras/` ничего не берёт (проверяет `test/api.test.js`) |

## Подключение

CommonJS, Node 20+, зависимость `playwright-core`. В npm не опубликован: вызывающие ставят его из клона (`npm install ../meatsuit`, зависимость `file:`). `package.json`: `"main": "index.js"`, поля `exports` нет,
поэтому доступны и вложенные модули (`require('meatsuit/hands.js')`, `require('meatsuit/telegram.js')`).
Экспорт — литерал `module.exports = { … }`: проекты на ESM берут имена из него напрямую.

```js
const {
  connect,                                            // вход
  hands, replay,                                      // руки на своей странице; воспроизведение записи
  signature, normalizeName, urlPattern,               // подпись экрана (архив)
  NeedsHuman, LimitReached, BudgetExceeded, BadCommand, StaleElement, FieldMismatch, // ошибки
  telegramNotifier, createTelegram, findChats, TelegramError,       // помощник Telegram
  peek,                                               // остаток лимита площадки без траты слота
  holdState, releaseHold,                             // стоп площадки после NeedsHuman: узнать, снять
} = require('meatsuit');
const { validate } = require('meatsuit/hands.js');   // проверка команды без браузера:
// validate(command, allowedHosts = [], { uploadDirs = [] } = {}) — бросает BadCommand
```

Список экспортов закреплён тестом (`test/api.test.js`); меняется только вместе с вызывающими.

## connect и task

```js
const ms = await connect({ cdpUrl, sitesFile /* или sites */, dir?, notify?, notifyOn?, ownerPresent? });
const result = await ms.task(name, async ({ see, act }) => { ...; return value; },
  { site, extraHosts = [], uploadDirs = [], maxCommands = 60, maxMinutes = 10, dryRun = false,
    dryRunNavigation = false, readOnly = false, capture?, codeLogin = false });
await ms.close();
```

| Параметр | Смысл |
|---|---|
| `cdpUrl` | адрес CDP общего браузера; обязателен |
| `sitesFile` или `sites` | лимиты площадок **вызывающего**: путь к его `sites.json` (читается на каждую задачу, правка действует без перезапуска) или объект того же вида. Ровно одно из двух; без них, с обоими или с несуществующим файлом `connect` падает до подключения к браузеру. Образец — `sites.example.json` |
| `dir` | замки очередей площадок `queue/<ключ>.lock`, счётчики `limits.json`, журнал `journal.jsonl`, повадки человека `persona.json`, отметки вкладок `tabs.json`, стопы площадок `holds/`, руль хозяина `wheel.json` и короткие замки `state.lock` вокруг общих файлов и `wheel.lock` вокруг руля; по умолчанию `~/.meatsuit`. **Все вызывающие одного браузера должны указывать один `dir`**: иначе у них разные замки, два бота пойдут на одну площадку одновременно, а руль хозяина остановит только часть из них. С зеркалом из `docker/` это папка `state/` в томе `meatsuit_profile` (см. «Подключение к зеркалу») |
| `notify(text, event)` | асинхронная функция уведомлений вызывающего. Сбой отправки задачу не роняет, пишется в stderr |
| `notifyOn` | какие события слать: `'start'`, `'done'`, `'limit'`, `'error'`, `'needsHuman'`; по умолчанию `['needsHuman', 'limit', 'error']` |
| `ownerPresent` | необязательно: асинхронная функция вызывающего, держит ли хозяин управление в зеркале, → `true`, `false` или `{ present }` (`check()` из `extras/presence.js` подходит как есть; пароль админа Neko остаётся у вызывающего). Спрашивается раз в 2 секунды, пока живо подключение. Ответ «да» включает руль хозяина для всех вызывающих того же `dir`, см. «Хозяин у руля». Функция бросила — считается «нет»; не функция — ошибка до браузера |
| `site` | хост площадки, ключ в `sites.json`; им же ограничивается `goto` |
| `uploadDirs` | массив абсолютных путей к каталогам, откуда `upload` берёт файлы (резюме, письма). Без него `upload` — `BadCommand`. Неверный вид — ошибка до очереди и браузера |
| `extraHosts` | массив хостов (`['company.com']`, без схемы, пути и `*`), где страница может оказаться без стопа: страница «спасибо» на сайте компании после формы ATS. Поддомены тоже. `goto` туда нельзя, лимиты и счётчики — по `site`; guard (капча, вход, блокировка) работает и там. Неверный вид — ошибка до очереди и браузера |
| `maxCommands`, `maxMinutes` | бюджет задачи; потолок задаёт площадка (`sites.json`), проект может выбрать меньше. `maxMinutes` проверяется перед каждой командой; задачу, которая идёт ещё 15 минут сверх него (страница не отвечает, повисло ожидание в коде вызывающего), meatsuit заканчивает сам: `BudgetExceeded`, окно закрывается (после `NeedsHuman` остаётся человеку), очередь свободна |
| `dryRun`, `dryRunNavigation` | репетиция, см. «Руки» |
| `readOnly` | задача только читает: тратит `perHour`, а `perDay` не тратит и им не останавливается. Первая команда записи (`fill`, `type`, `select`, `upload`, `press Enter`, `click` не по `tab`) засчитывает полный слот дня до своего выполнения; если день исчерпан — `LimitReached`, команда не выполняется |
| `capture` | архив экранов `{ dir, htmlPerSignature = 5, maxMB = 500 }`; без него ничего не пишется |
| `codeLogin` | `true` — задача входит по одноразовому коду (см. «Вход по коду» ниже). Нужна ещё своя запись площадки с `codeLogin` в `sites.json`; без неё, с неверным правилом или со значением не `true`/`false` — ошибка до очереди и браузера |

`task` по порядку: площадка на стопе — сразу `NeedsHuman` с `onHold: true` (см. «Стоп площадки») → ждёт, пока
руль у хозяина → встаёт в очередь **своей площадки** (один бот за раз на площадке, замок-файл работает между
процессами) → проверяет лимит площадки и записывает задачу (`dryRun` слотов не тратит) → открывает своё окно (с
`singleTab` — берёт вкладку площадки) → зовёт функцию под присмотром guard и бюджета → закрывает окно. На `NeedsHuman`
окно остаётся открытым: человек решает в зеркале. Новые вкладки, открытые страницей, закрываются. Возвращает то, что
вернула функция.

### Несколько ботов в одном браузере

Один прогретый браузер обслуживает нескольких ботов сразу (tinder-matcher, cvs, датчик Telegram; из разных процессов
или из одного): **очередь своя у площадки**, общая у всех вызывающих одного `dir`.

- Задачи **разных площадок идут одновременно**, каждая в своей странице: своё новое окно, открытое в фоне
  (`Target.createTarget` с `newWindow` и `background`: фокус экрана оно не забирает), или с `singleTab` своя вкладка
  площадки, которую задача ищет по своему хосту и его поддоменам. Задача никогда не берёт, не снимает и не закрывает
  страницу другой площадки и страницу, где работает другая задача: поиск `singleTab` пропускает вкладку на своём хосте,
  которую держит идущая задача (попавшая туда по своим `extraHosts`). Свои страницы задачи одного процесса знают сами;
  задачу другого процесса видно по CDP target id её окна, который каждая задача пишет в свой замок очереди
  `queue/<ключ>.lock` (замок, не обновлявшийся 30 секунд, считается брошенным). Команды задачи идут по CDP в её
  страницу (клавиши — в элемент в фокусе этого документа, мышь — в эту страницу) и от того, какое окно в фокусе на экране, не зависят. Вперёд ядро выводит страницу в одном случае:
  окно или вкладку, которые после `NeedsHuman` остаются человеку, чтобы не искать их в зеркале, и только пока руль
  свободен.
- Задачи **одной площадки идут по одной**, в порядке, в каком взяли замок. Площадка и её поддомены — одна очередь:
  ключ — два последних звена хоста (`web.telegram.org` и `telegram.org`, `www.linkedin.com` и `linkedin.com`), потому что
  задача `singleTab` ищет вкладки и по поддоменам. Площадки под общим суффиксом вроде `co.uk` тоже окажутся в одной
  очереди: лишнее ожидание, но никогда две задачи в одной вкладке. Адрес IPv4 и одно звено (`localhost`) — ключ как есть.
  Лимиты и стопы по-прежнему по точному `site`.
- Задача ждёт очередь своей площадки до 30 минут; если площадка всё ещё занята, `task` бросает `LimitReached`
  («очередь <ключ>: занята задачей «…» (площадка) с ЧЧ:ММ»), не трогая браузер и не тратя слот: вызывающий обходится
  с этим как с лимитом и повторяет позже, а не считает своей поломкой. Пока работает `fn`, ждут остальные задачи этой
  площадки, в том числе пока ваш код ждёт модель: ставьте сроки своим ожиданиям внутри `fn` (`maxMinutes` проверяется
  перед каждым `see`/`act`, а не пока ждёт ваш код). Задачу, которая идёт ещё 15 минут сверх своего `maxMinutes`,
  meatsuit заканчивает сам: одна зависшая задача не держит свою площадку вечно.
- **Руль хозяина один на весь браузер** (ниже): пока он у хозяина, не начинается задача ни одной площадки, не
  начинается ни одна команда, а `fill` или `type`, которые уже печатают, останавливаются примерно за 2 секунды. Стопы
  площадок и лимиты — по-прежнему у каждой площадки свои.
- Общие файлы `dir` (`limits.json`, `tabs.json`) читаются, правятся и пишутся под коротким замком `state.lock`: задачи
  разных площадок, пишущие одновременно, ничего не теряют; `limits.json` заменяется целиком, читатель никогда не видит
  половину. Если `state.lock` не освободился за 60 секунд (процесс завис, держа его, и всё ещё обновляет), `task`
  бросает `LimitReached`, и текст называет `state.lock`. Один `capture.dir` можно давать нескольким задачам: номер снимка занимается созданием файла
  (`html-counts.json` тогда может насчитать чуть меньше сохранённого).
- Проверено в Chromium без экрана и с двумя–четырьмя процессами Node на одном браузере (`test/parallel.test.js`) и
  измерено один раз в одноразовом локальном зеркале Neko 08.11.2026 (образ `google-chrome:3.1.6`, Chrome 154, openbox;
  без сети и томов; хозяина изображал `xdotool`): две задачи печатали одновременно, и каждый текст целиком пришёл в своё
  поле, какое бы окно ни было в фокусе. Без `background` каждое новое окно задачи забирало фокус экрана, и буквы,
  которые набирал хозяин, уходили в поле бота; с ним открытие окна ничего не меняет, но **клик бота всё равно
  активирует его окно** (Chrome делает это при нажатии мыши), и буквы хозяина снова уходили в поле бота. С рулём у
  хозяина все 20 его букв остались в его поле и активное окно не менялось; когда он отдал руль, оба бота пошли
  одновременно; стоп на капче вывел своё окно вперёд. Итого: боты друг другу не мешают, а хозяину, который печатает,
  мешают — говорите им рулём. **Не проверено:** настоящая клавиатура через веб-клиент Neko, сервер владельца и каково
  нескольким окнам сразу на слабом процессоре.

**Обновление с версии, где очередь одна на весь браузер.** Та версия держала один замок `<dir>/queue.lock`. Задача
этой версии ждёт, пока живой `queue.lock` есть (вызывающий, которого ещё не обновили, ведёт задачу), а прежняя версия о
замках площадок не знает: её задача может начаться, пока идут задачи этой, в том числе на той же площадке. Обновлять
всех вызывающих одного `dir` вместе (пересобрать их образы). В своём коде вызывающим менять нечего: те же `connect` и
`task`; задачи разных площадок теперь просто идут одновременно.

### Хозяин у руля

Пока хозяин сам работает в зеркале, боты ждут: клик бота активирует окно бота, и буквы, которые набирает хозяин,
уходят в поле бота (измерено, см. выше); сайт к тому же увидел бы две руки. Руль — файл `<dir>/wheel.json`
(`{ by, since, until }`, мс), действует, пока `until` впереди; битый файл — как нет руля.

```js
const { wheelState, takeWheel, releaseWheel } = require('meatsuit/wheel.js');
await takeWheel({ dir, minutes = 60 });   // хозяин взял: → { by: 'owner', since, until }; более длинный руль не укорачивается
await releaseWheel({ dir });              // → { released }
wheelState({ dir });                      // → { by, since, until } или null
```

`takeWheel` и `releaseWheel` асинхронные: прочитать, решить и записать руль они успевают под коротким замком
`<dir>/wheel.lock`, поэтому «да» зеркала из одного процесса и `take` хозяина из другого в один и тот же миг не затирают
друг друга (руль хозяина, ставший рулём `mirror`, снял бы следующий ответ «нет»). Замки берутся в одном порядке: сначала
замок очереди площадки, потом `wheel.lock` или `state.lock`; каждый из этих двух держится на одно чтение и одну запись,
под ним ничего не берётся, и вместе они не держатся никогда.

Из консоли: `node tools/wheel.js take [минуты] [--dir …]`, `give`, без команды — состояние (`--dir` по умолчанию —
`MEATSUIT_DIR`, иначе `~/.meatsuit`). С `connect({ ownerPresent })` ядро спрашивает функцию вызывающего раз в 2 секунды
всё время, пока живо подключение (от `connect` до `close()` или обрыва связи с браузером), в том числе когда у самого
вызывающего задач нет, и не чаще, когда задача ждёт или печатает; «да» пишет руль `by: 'mirror'` на 30 секунд и
продлевает, пока ответ «да», «нет» снимает только руль `mirror` (взятый хозяином руками — никогда). Так один
подключённый вызывающий, который знает про Neko, останавливает всех вызывающих того же `dir`, занятых и простаивающих;
если он перестал работать, его последнее «да» держит остальных не дольше 30 секунд. Таймер процесс вызывающего не
держит. Вызывающий в сети зеркала достаёт Neko по `127.0.0.1:8080`; пароль
админа — его собственная настройка:

```js
const { createPresence } = require('meatsuit/extras/presence.js'); // только fetch, зависимостей extras/ не тянет
const presence = createPresence({ url: 'http://127.0.0.1:8080', password: nekoAdminPassword });
const ms = await connect({ cdpUrl, dir, sitesFile, ownerPresent: () => presence.check() });
```

- До очереди: пока руль у хозяина, задача не встаёт в очередь своей площадки и не открывает окно. Руль взяли, пока она
  ждала замок, — замок она отдаёт и ждёт снаружи.
- В идущей задаче: `act()` ждёт перед каждой командой; `see()` не ждёт (он ничего не нажимает). Окно и очередь
  площадки остаются за задачей. Время у руля не входит ни в `maxMinutes`, ни в срок сторожа зависшей задачи.
- В идущей команде: `fill` или `type`, которые уже печатают, смотрят руль между клавишами не чаще раза в 2 секунды и,
  если его взяли, останавливаются: `LimitReached` с `.wheel` и **без** `.before` (часть текста уже в поле),
  `notify('limit')`. Enter в это поле потом не нажмётся (`FieldMismatch`), пока в нём не будет набранное ботом (см.
  «Поле после ввода»): полсообщения не уйдёт. Прочая начатая команда (клик с путём мыши, прокрутка, `wait` до 15 с)
  доходит до конца: это секунды.
- Ждёт не дольше 30 минут за раз, потом `LimitReached` с `.wheel` (состояние руля): до очереди задача не начиналась
  (окна и слота нет), из `act()` — с `.before = true`, команда не выполнялась. Оба раза `notify('limit')`.

### sites.json

```json
{ "example.com": { "perDay": 20, "perHour": 6, "hours": "10-23", "maxCommands": 80, "maxMinutes": 15 },
  "example.org": { "perDay": 0 },
  "*":           { "perDay": 3, "perHour": 2, "hours": "9-21", "maxCommands": 80, "maxMinutes": 12 } }
```

- Правило ищется по точному ключу `site`. Необязательный `"*"` — правило для хостов, которых в файле нет;
  счётчики всё равно по хосту. Явная запись заменяет `"*"` целиком и с ним не сливается.
- Без `"*"` неописанный хост даёт `LimitReached`. Поддомен описанной площадки под `"*"` не попадает.
  `site: '*'` — ошибка.
- `perDay: 0` — площадка закрыта. `hours` — часы работы по поясу процесса (`TZ`).
- `singleTab: true` — площадка держит одну активную вкладку: задача идёт в уже открытой вкладке этой площадки
  и не закрывает её; вкладка проверяется guard до траты слота (капча, оставленная человеку, не трогается).
  `singleTab` читается **только из правила `sites.json`** (своей записи или `"*"`); опции `task` с таким
  именем нет, переданная в `task(..., { singleTab })` ничего не меняет.
- `staleTabHours` (по умолчанию `48`, `0` — выключено) — только при `singleTab`. Если вкладок площадки несколько,
  рабочая — та, что на экране, иначе с самой свежей активностью. Перед задачей закрываются остальные вкладки
  площадки без активности дольше `staleTabHours` часов. Активность — задача шла во вкладке, сменились адрес или
  заголовок, вкладка на экране (`visibilityState`); вкладка, которую ядро видит впервые, получает «сейчас». Не
  закрываются: рабочая, на экране, с капчей, входом или блокировкой, с набранным текстом в поле, ещё загружающаяся;
  при `dryRun` не закрывается ничего. Отметки — в `<dir>/tabs.json` (CDP target id → хеш адреса и заголовка и
  время), на странице ничего не меняется. Закрытая вкладка — строка журнала `cmd: { cmd: 'closeTab' }`, `url` без
  query и hash, `idleHours`. Активность видна только в моменты проверок (раз за задачу).
- `codeLogin: { "path": "^/account/login", "maxMinutes"?: 6 }` — путь, где задача с `task(..., { codeLogin: true })`
  может пройти вход по одноразовому коду. Читается **только из своей записи площадки**, из `"*"` — никогда.
- `holdHours` (по умолчанию `6`, `0` — стоп не ставить) — на сколько часов площадка встаёт на стоп после
  `NeedsHuman`, см. «Стоп площадки».

### Стоп площадки после NeedsHuman

Любой `NeedsHuman` задачи (guard ядра — капча, вход, блокировка, уход с площадки — или брошенный кодом вызывающего)
ставит **стоп этой площадки** на `holdHours` часов. Пока стоп стоит, `task` этой площадки сразу бросает
`NeedsHuman` с `onHold: true`: не ждёт очередь, не трогает вкладки и окна, не тратит слот и **не шлёт `notify`**
(о стопе сообщили, когда его ставили). Другие площадки того же браузера работают. Стоп действует и на `dryRun`.
Решённая капча стоп не снимает: снимает человек или срок. После срока следующая задача идёт как обычно; если капча
всё ещё на вкладке, guard снова даст `NeedsHuman` и новый стоп — выходит напоминание раз в `holdHours`.

```js
const h = holdState(site, { dir? });       // → { site, reason, url, since, until } (мс) или null
const { released } = releaseHold(site, { dir? }); // снять раньше срока; released — был ли действующий стоп
```

Без браузера и без очереди; `dir` — тот же, что у `connect` (по умолчанию `~/.meatsuit`). Из консоли:
`node tools/release.js <площадка> [--dir …]` (без площадки — список стопов; `--dir` по умолчанию `MEATSUIT_DIR`, иначе `~/.meatsuit`; `connect` эту переменную не читает,
поэтому сообщение `NeedsHuman` на стопе печатает команду с `--dir` своей задачи).
У `NeedsHuman`, который стоп поставил, тоже есть `.hold` — до какого времени (`until`) площадка стоит. Файлы —
`<dir>/holds/<площадка>.json`, их формат не контракт.

### Вход по коду (codeLogin)

Обычно страница входа — стоп. Узкое исключение для входа по коду из SMS (вызывающий получает код от человека,
например через remora `/ask`, и вписывает его сам). Стоп «страница входа» снимается, только если сошлось всё:

1. задача попросила: `task(name, fn, { site, codeLogin: true })`;
2. у площадки в `sites.json` вызывающего своя запись с `codeLogin.path` — регулярное выражение пути с якорем
   `^/` (один путь, например `"^/account/login"`; `"^/"` и путь без якоря — ошибка);
3. адрес — `https` на хосте `site` или его поддомене (не на `extraHosts`), и `pathname` подходит под `path`
   (query не учитывается);
4. на странице нет поля пароля (`inputType: 'password'` или поле с именем «пароль»/«password»).

Порядок guard прежний: капча → блокировка или «подозрительная активность» → вход. Капча, блокировка, страница вне
площадки, поле пароля, другой путь или площадка — `NeedsHuman`, как без `codeLogin`. Бюджет такой задачи урезан:
не больше 20 команд и не дольше `codeLogin.maxMinutes` (если задано; потолок `maxMinutes` площадки действует
всё равно). Набранный код в журнал не попадает (`fill` пишется длиной, адреса — без query и hash). Пароли meatsuit
не вводит никогда: вызывающий передаёт только идентификатор (телефон или почту) и код.

### peek: остаток лимита без траты слота

```js
const st = peek(site, { sitesFile /* или sites */, dir?, now?, readOnly? });
// → { site, rule, ok, reason, usedDay, usedHour, leftDay, leftHour }
```

Для проверки перед запуском и отчётов: без браузера, без очереди, `limits.json` не пишет. `sitesFile`/`sites`
и `dir` — те же, что у `connect` (и те же ошибки файла лимитов). `rule` — правило площадки (своё или `"*"`,
`null` — площадки нет); `ok` — задача сейчас запустилась бы; `reason` — текст `LimitReached`, с которым не
запустилась бы (вне часов, лимит дня или часа, `perDay: 0`, площадки нет), иначе `null`. `usedDay` — задачи с
записью с местной полуночи, `usedHour` — все задачи (и `readOnly`) за последний час; `leftDay`/`leftHour` —
сколько ещё можно (`null` — лимита нет, `0` — площадки нет). `readOnly: true` — как у `task`: `perDay` не
останавливает. Кривое правило (например `hours`) — исключение, как у `task`. Внутренние `meatsuit/limits.js`
не импортируйте: их формат не контракт.

### Ошибки

| Ошибка | Когда | Что делать проекту |
|---|---|---|
| `LimitReached` (`.wheel`, `.before`) | площадки нет в `sites.json` (и нет `"*"`), `perDay: 0`, вне часов, лимит дня или часа; очередь площадки 30 минут занята другой задачей (в тексте — её имя и площадка); хозяин 30 минут не отпускает руль (`.wheel`; из `act()` — с `before: true`, команда не выполнялась); хозяин взял руль посреди `fill` или `type` (`.wheel` без `.before`: часть текста набрана); короткий замок `state.lock` или `wheel.lock` занят дольше срока (текст называет его) | задачу не начинать, повторить позже; после оборванного `fill` — заполнить поле заново, а не жать Enter |
| `NeedsHuman` (`.reason`, `.url`, `.before`, `.hold`, `.onHold`) | капча, страница входа (кроме объявленного пути задачи с `codeLogin`), блокировка, уход с хоста площадки (и не на `extraHosts`); площадка на стопе (`onHold: true`) | остановиться; окно открыто для человека. Площадка встаёт на стоп (`.hold.until`); `onHold: true` — задача и не начиналась, это не сбой и не повод повторять до `until`. Состояние не снимается до конца задачи. Из `act()`: с `before: true` стоп пришёл из проверки до команды и **команда не выполнялась**; без него команда выполнилась, а стоп — про страницу после неё (сообщение могло уйти, форма — отправиться) |
| `BudgetExceeded` | больше `maxCommands` команд или `maxMinutes` минут | считать задачу неудачной |
| `StaleElement` | `gen` устарел, элемента нет, под курсором перед нажатием не цель, фокус ушёл | взять свежий снимок |
| `FieldMismatch` (`.cmd`, `.id`, `.expectedLength`, `.actualLength`, `.diffAt`, `.before`) | после `fill` или `type` в поле не тот текст (кто-то печатал вместе с ботом или страница поменяла ввод); `type` или `Enter` в поле, где уже не то, что набрал бот (`before: true`: ничего не набрано и не нажато). Только длины, текста нет | не повторять вслепую: сказать хозяину или проверить поле через `see()`; см. «Поле после ввода» |
| `BadCommand` | команда не из набора или с плохими полями; неверные `within`, `tree`, `items` или `textLimit` у `see()` | ошибка вызывающего кода или модели |

## Подключение к зеркалу

Зеркало из `docker/` (см. [docker/README.md](../docker/README.md)) держит постоянные имена:

- контейнер `meatsuit-browser`: вызывающий подключается `network_mode: "container:meatsuit-browser"`,
  `cdpUrl: 'http://127.0.0.1:9222'` (наружу CDP не публикуется);
- том `meatsuit_profile` (постоянное `name:`, корень и папка `state/` принадлежат uid 1000; создаётся при любом
  браузере). Вызывающие подключают его как `external` и держат общий `dir` в его папке `state/`:
  `connect({ dir: '<точка монтирования>/state' })`. Процесс бота пишет в `state/`, поэтому работает от uid 1000
  (пользователь `node` в образах Node) или от root. В томе же лежит профиль Chrome: подключайте его только туда,
  где это нужно, и только для чтения там, где писать не нужно.

## Глаза: `see(opts?)`

```js
const snap = await see();                                    // полный снимок
const snap = await see({ screenshot: true });                // + JPEG q60 в base64
const snap = await see({ settle: { minElements, quietMs, timeoutMs } }); // ждать отрисовку SPA (до 15 с)
const diff = await see({ since: prevSnap });                 // только изменения
const snap = await see({ within, tree, items, textLimit });  // + чтение по запросу, см. ниже
```

Снимок: `{ gen, url, title, text (до 6000), textParts?, elements[{ id, role, name, inView, value?, checked?,
disabled?, focused?, selected?, href?, inputType?, options?, optionsTotal? }], dialogs[{ name, text, elements }],
frames, hiddenFrames, screenshot? }`. Номера `id` действуют только внутри своего `gen`; после любой команды — новый
`gen`. Значение поля пароля не отдаётся никогда. Открытые shadow-корни входят в снимок; закрытые и содержимое
чужих iframe — нет (видны только адреса в `frames`).

Поля по видам элементов:

| Элемент | `role` | Что ещё |
|---|---|---|
| поле ввода, `textarea`, `contenteditable` | `textbox` | `value` — первые 80 символов значения |
| `<select>` | `select` | `value` — **подпись** выбранного варианта (несколько — через запятую); `options` — подписи вариантов по порядку, до 100; если вариантов больше — `optionsTotal` (всего) |
| поле пароля | `textbox` | `inputType: 'password'`, без `value` |
| поле файла `<input type=file>` | `button` | `inputType: 'file'`; `value` — имена прикреплённых файлов через запятую (`''`, пока ничего нет), по ним видно, что резюме встало. Спрятанное поле (`display:none`, `hidden`, `opacity:0`) или накрытое своей меткой в снимке есть, если видна его метка (`label for` или обёртка) или кнопка в том же родителе: `inView` по ней, `name` — своё или её |

Результат `see()`/`act()` проходит guard: капча (в том числе в iframe, кроме невидимой reCAPTCHA), вход
(кроме входа по коду, см. «Вход по коду»), блокировка → `NeedsHuman` вместо результата. Перед командой, которая
трогает страницу (`click`, `fill`, `type`, `press`, `select`, `upload`), страница проверяется ещё раз по свежему
снимку: капча, блокировка, вход или чужой хост, появившиеся, пока вызывающий думал, останавливают задачу до команды,
а не после неё. Этот снимок не возвращается и `id`/`gen` не меняет.

### Чтение по запросу: `within`, `tree`, `items`

```js
const s = await see({
  within: { role: 'region', name: 'Message history' },  // или { css: '#column-center' }
  tree: true,                                            // дерево без обёрток для within (или всей страницы)
  textLimit: 12000,                                      // для within.text и tree: по умолчанию 6000, не больше 20000
  items: { css: '[role=article]', last: 20,              // или first: N; не больше 50
           flags: { out: '.is-out' },                    // имя → CSS-селектор, которому отвечает сам item
           attrs: ['data-mid'],                          // data-*, datetime, alt, title, href, aria-label
           textLimit: 600 },                             // на один item: по умолчанию 600, не больше 2000
});
// s.within → { text, elements: [номера] } или null; s.tree → строка или null
// s.items  → [{ text, inView, id?, flags?, attrs? }] или null; s.itemsTotal, если нашлось больше
```

Эти опции только добавляют поля. Остальной снимок (`text`, `elements`, `dialogs`, …) тот же, что без них, и guard
смотрит его, поэтому капча вне `within` останавливает задачу так же. Опции говорят, что прочитать (селекторы и имена
атрибутов); читает собственный изолированный мир meatsuit, JavaScript вызывающего не выполняется.

- `within` — первый видимый элемент (с открытыми shadow-корнями), который отвечает `css` или у которого такие
  `role` и `name` (как в снимке: `elements[].name`, `dialogs[].name` или `aria-label`; без `name` — первый с этой
  ролью). Роль — атрибут `role`, роль снимка у интерактивного элемента или по тегу: `heading`, `list`, `listitem`,
  `article`, `dialog`, `time`. `within.text` — его текст до `textLimit`, строками: часть не глубже двух уровней
  (сообщение со временем, строка списка со ссылкой, абзац со ссылкой) — одна строка, часть крупнее делится на детей.
  `within.elements` — номера элементов снимка внутри. Не нашёлся — `within`, `tree` и `items` равны `null`.
- `tree: true` — содержимое строками в духе YAML: текст (`- Привет!`) и узлы с ролью (`- [button #7 "Send"] ➤`),
  где `#7` — номер элемента в этом снимке, а имя пишется, только если оно говорит то, чего нет в тексте (подпись
  поля, `aria-label` кнопки-иконки, `datetime` у `time`). Обёртка без роли пропадает, если пустая, становится своим
  ребёнком, если он один, и остаётся группой (`- - …`), если их несколько: у сообщения текст и время остаются
  вместе. Строчные обёртки слова не рвут. Не входят: скрытое (`display:none`, `visibility:hidden`,
  `content-visibility:hidden`, закрытый `<details>` дальше `<summary>`), `<script>`, `<style>`, `<svg>`, iframe и
  содержимое `input`, `textarea`, `select` и узлов `textbox` (их значения — в `elements`, имя поля — как там).
  Обрезается до `textLimit` с `…`.
- `items` — видимые элементы под `css` (внутри `within`, если он задан), первые (`first`) или последние (`last`) N
  в порядке документа. У каждого `text` (строками, как `within.text`: сообщение или строка списка — одна строка) и
  `inView`; `id`, если item сам элемент снимка (ссылка строки чата — по ней click); `flags` — для каждого имени, отвечает ли item селектору (`{ out: '.is-out' }` для пузыря Telegram Web
  K, у которого сторона есть только в классе); `attrs` — те из запрошенных атрибутов, что у item есть, значения до
  200 символов, из закрытого списка: `data-*`, `datetime`, `alt`, `title`, `href`, `aria-label`. `value` нельзя
  никогда, у поля пароля атрибуты не читаются. Селектор атрибуты видит, поэтому флаг может проверить, что в атрибуте
  записано, в том числе `value`, заданный в HTML; то, что человек набрал в поле, — не атрибут, его не видит ни один
  селектор.
- В тексте `within`, `tree` и `items` `alt` картинки стоит на её месте (эмодзи, нарисованные `<img alt>`). `text`
  снимка и имена элементов — как раньше.
- С `since` diff несёт `within`, `tree`, `items` и `itemsTotal` целиком; `changed` их не учитывает, сравнивает
  вызывающий.
- Неверная опция (лишнее поле в `within` или `items`, оба или ни одного из `first` и `last`, атрибут не из
  списка, `textLimit` без `within` и `tree`, селектор, который не разбирается) — `BadCommand` до снимка; прошлый
  снимок и его номера остаются годными. Числа выше потолка срезаются до потолка.

## Руки: `act(command)`

Набор закрытый, всё остальное — `BadCommand` до выполнения.

| Команда | Поля | Примечание |
|---|---|---|
| `click` | `id`, `gen` | прокрутка, мышь по кривой, клик в случайную точку; перед нажатием проверка, что в точке цель. По полю файла — `BadCommand` (открыло бы системное окно выбора; для файлов `upload`) |
| `fill` | `id`, `gen`, `text` | клик, проверка, что фокус в поле, очистка, ввод, проверка, что в поле `text` (см. «Поле после ввода»). `text` до 1000 символов в одну строку; в `<textarea>` — до 2000 и с переводами строк, см. ниже. По `<select>` и полю файла — `BadCommand` (для них `select` и `upload`) |
| `select` | `id`, `gen`, `value` или `label` | вариант нативного `<select>`, см. ниже |
| `upload` | `id`, `gen`, `file` | файл из `uploadDirs` в форму, см. ниже |
| `type` | `text`, `id?`, `gen?` | ввод в фокус, одна строка; с `id`/`gen` фокус сверяется перед первой клавишей; после ввода в поле должно быть прежнее плюс `text` с места курсора |
| `press` | `key`, `id?`, `gen?` | `Enter` `Escape` `Tab` `Backspace` `ArrowDown` `ArrowUp` `PageDown` `PageUp`. `Enter` в поле, куда печатали эти руки, — только пока в поле то, что они набрали |
| `scroll` | `px?`, `id?`, `gen?` | вниз, от 0 до 5000; с `id`/`gen` мышь сначала наводится на элемент (без клика) и колесо крутится над ним: так двигается вложенная прокрутка, например список в боковой панели |
| `wait` | `ms` (до 15000) или `text` | пауза или появление текста |
| `back` | — | назад по истории |
| `goto` | `url` | только `https:` и только хост площадки или его поддомен |

Возвращает diff снимка после команды. `dryRun: true`: `see` работает, `act` возвращает `{ dryRun: true,
changed: false }` и только пишет в журнал (`upload` перед этим проверяет файл); исключение — `goto` выполняется.
`dryRunNavigation: true` дополнительно выполняет `click` по элементу с ролью `tab` (переключение вида), если над
ним нет ссылки, кнопки, поля или метки, и `scroll` (только двигает вид; так репетиция видит подгружаемый прокруткой список).

### Поле после ввода: FieldMismatch

`fill` и `type` сверяют поле после последней клавиши, а `press Enter` — ещё раз прямо перед клавишей:

- после `fill` значение поля (у `contenteditable` — видимый текст, `innerText`) должно равняться `text`; после
  `type` — прежнему содержимому со вставленным на месте курсора `text`. Обе стороны сначала нормализуются: `\r\n` →
  `\n`, неразрывный пробел → пробел, Unicode NFC, пробелы по краям срезаются;
- `type` в поле, куда печатали эти руки и где теперь другое, и `press Enter` в такое поле (в то, что в фокусе, с `id`
  или без) бросают `FieldMismatch` с `before: true`: ничего не набрано и не нажато. После прошедшего Enter поле
  забывается; новый `fill` начинает заново. Что набрали руки, помнит изолированный мир meatsuit в этом документе (не
  диск, страница его не видит), пока документ не сменится, — его видит и следующая задача в той же вкладке;
- перед `Ctrl+A` `fill` сверяет, что фокус в цели (или внутри неё): страница могла увести его после клика, и очистка
  стёрла бы другое поле. Не в цели — `StaleElement`, ничего не стёрто и не набрано;
- если после последней клавиши поля уже нет или документ сменился (страница сама приняла ввод: код с проверкой по
  последней цифре, отправленная форма), сверять не с чем, и команда выполнена, как раньше.

У `FieldMismatch` есть `cmd` (`'fill'`, `'type'` или `'press'`), `id` (как в команде, может быть `undefined`),
`expectedLength` и `actualLength` (после нормализации), `diffAt` (номер первого несовпавшего знака с нуля) и
`before: true`, когда ничего не набрано и не нажато. Ни в сообщении, ни в полях текста нет: это личное сообщение, а
ошибка уходит в журнал и в `notify`. Без `before` клавиши набраны, и в поле не `text`.

Так бывает, когда кто-то печатает вместе с ботом (хозяин в зеркале: клик бота активирует окно бота, и буквы, которые
набирает хозяин, уходят в поле бота, см. «Несколько ботов в одном браузере»), а ещё когда страница сама меняет ввод:
маска телефона, обрезка по `maxlength`, код из нескольких полей, где фокус после каждой цифры уходит в следующее (в
первом тогда одна цифра). Не повторять вслепую: сказать хозяину или посмотреть поле через `see()` (его `value`, первые
80 символов) и решить. Enter в это поле не нажмётся, пока в нём не будет набранное ботом; `click` по кнопке отправки
не сверяется. Проверено в headless Chromium (`test/hands.test.js`: буквы посреди `fill` и `type` в `textarea` и
`contenteditable`, правка между `fill` и Enter, страница уводит фокус после клика); в Chrome под Neko живьём не
проверено.

### fill в textarea (сопроводительное письмо)

`validate` пропускает `fill` с текстом до 2000 символов и с переводами строк (`\n`, `\r\n` приводится к `\n`).
При выполнении, когда цель известна: такой текст (с переводом строки или длиннее 1000) — только в `<textarea>`;
в обычное поле, `contenteditable` и прочее — `BadCommand` до любого действия. `type` остаётся одной строкой до 1000.

Перевод строки печатается как **Shift+Enter**: в обычном `textarea` это та же новая строка, а в чате голый Enter
отправил бы полсообщения. Печать идёт в темпе персоны (150–475 знаков в минуту, с опечатками и исправлениями):
2000 знаков — это 4–13 минут. `maxMinutes` задачи (и потолок площадки в `sites.json`) должны это вмещать: срок
проверяется перед каждой командой, длинный `fill` им не обрывается, но следующая команда получит `BudgetExceeded`.
Руль хозяина его обрывает (см. «Хозяин у руля»).

### upload

`{ cmd: 'upload', id, gen, file }`. `file` — абсолютный путь; `validate(c, hosts, { uploadDirs })` пропускает только
файл внутри одного из `uploadDirs` (без `..`, не соседний каталог с тем же началом имени), с расширением `pdf`,
`doc` или `docx` без учёта регистра. Без `uploadDirs` — `BadCommand`. При выполнении (и в `dryRun`) ещё раз, по
настоящему пути: ссылка (symlink) не выводит из `uploadDirs` и не ведёт на другой тип, это обычный непустой файл
не больше 10 МБ, иначе `BadCommand` до любого действия. В сообщениях об ошибке пути нет.

Файл передаётся в браузер **буфером** (`{ name, mimeType, buffer }`), не путём: браузер может жить в другом
контейнере, где пути с хоста нет. Имя — последняя часть `file`, тип — по расширению.

Цель `id` — одно из двух:

- **поле `<input type=file>`** (видимое или спрятанное за меткой, см. «Глаза»): после паузы «выбрал в окне» файл
  ставится в поле, как `setInputFiles` у Playwright с буфером; страница получает `input` и `change` (синтетические,
  `isTrusted: false`, как у Playwright). Поле `disabled` — `BadCommand`; поле исчезло за время паузы — `StaleElement`;
- **кнопка или метка, которая открывает выбор файла**: человеческий клик (с проверкой точки), окно выбора
  перехватывается (системное окно не открывается) и получает файл. Окна выбора нет за 5 с — `BadCommand`
  «не открыл выбор файла» (клик уже был: взять свежий снимок).

После команды в снимке у поля `value` — имя файла; часто имя появляется и в `text` страницы. `dryRun`: файл
проверяется, но не загружается, в журнале `{ cmd: 'upload', id, gen, fileType }` без пути и имени.

Не входит: несколько файлов за раз, перетаскивание в зону (drag-and-drop без поля), проверка `accept` поля.
`click` по кнопке выбора файла (вместо `upload`) откроет системное окно в зеркале — для файлов только `upload`.
Проверено в headless Chromium (`test/upload.test.js`); в Chrome под Neko и на настоящих ATS-формах живьём не проверено.

### select

`{ cmd: 'select', id, gen, label }` — по подписи варианта, как в `options` снимка (без учёта регистра и лишних
пробелов); `{ cmd: 'select', id, gen, value }` — по атрибуту `value` варианта (точно; `''` допустимо). Ровно одно из
двух, строка до 200 символов. Цель — нативный `<select>` без `multiple`.

Как у человека с клавиатурой: рука подходит к списку, он получает фокус, вариант выбирается стрелками без
раскрытия (раскрытый список браузер рисует отдельным окном, мышью до него не дотянуться); вариант дальше 25
позиций — сначала первыми буквами подписи (поиск по буквам у закрытого списка), потом стрелками. События `input`
и `change` настоящие (`isTrusted`). Если стрелки выбор не двигают (Chromium на macOS по стрелке раскрывает список),
набирается кратчайшее начало подписи, с которого не начинается ни один другой вариант, тоже настоящими клавишами.
Если браузер и так не двинул выбор, вариант ставится напрямую с событиями `input` и `change` (они синтетические, как
у `selectOption` в Playwright). Вариант уже выбран — ничего не делается.

`BadCommand` до любого действия: цель не `<select>`, `multiple`, список или вариант недоступен (`disabled`, в том
числе у `optgroup`), такого варианта нет. Проверено в headless Chromium (`test/forms.test.js`): на macOS 4 ноября, там работает путь с набором подписи, и на
Linux 5 ноября, где работают стрелки; в Chrome под Neko живьём не проверено.

### Темп рук

Все команды идут через `human.js` (руки ветки main): мышь по кривой со скоростью по закону Фиттса, дрожью и
изредка перелётом; до элемента ниже экрана — колесом, рывками с паузами; клик в точку около центра с задержкой
и удержанием кнопки; печать клавишами с ритмом, Shift и опечатками, которые тут же исправляются (план всегда кончается
ровно заказанным текстом, а `fill` и `type` потом сверяют поле, см. «Поле после ввода»); кириллица — событиями клавиш через CDP. Курсор уже над элементом — рука к нему
не едет. Перед нажатием мыши hands сверяет, что под курсором всё ещё цель (`StaleElement`, если нет).

Повадки человека (скорость руки, дрожь, подёргивания, темп печати `wpm`, доля опечаток `typoRate`) создаются
один раз и лежат в `<dir>/persona.json`: после перезапуска и у всех вызывающих одного `dir` в браузере тот же
человек. Испорченный файл заменяется годными повадками. Повадки общие на процесс: два `connect` с разными `dir`
в одном процессе — последний задаёт человека. Файл вне репозитория (в `dir`), в git не попадает.

## Журнал, запись, архив

- Журнал `<dir>/journal.jsonl`, строка на команду: `ts`, `dryRun`, `cmd`, `url`, `result: 'ok' | 'dry-run'`
  или `error`, `urlAfter`. Журнал хранит, что сделано и где, но **не что набрано**: в `cmd` только `cmd`, `id`,
  `gen`, `key`, `px`, `ms`; вместо `text`, `value`, `label` — их длины (`textLength`, `valueLength`,
  `labelLength`); у `upload` — только тип файла (`fileType: 'pdf'`), без пути и имени. Адреса (`cmd.url`, `url`,
  `urlAfter`) — без query и hash: там бывают токены входа, коды и набранный поиск. Ошибка — первая строка
  сообщения, из которой вычищены текст и адрес команды. Прочие поля команды не пишутся. Если строку журнала записать
  нельзя (нет прав на файл в общем `dir`, диск полон), команда не падает: строка теряется, причина уходит в stderr, —
  выполненный клик никогда не выглядит упавшим.
- Запись (`recordDir`) и архив (`capture`) — другое дело: там снимки и команды целиком, с текстом полей.
- `hands(page, { recordDir })` пишет снимки в `NNNN.json`; `replay(recordDir)` даёт тот же `{ see, act }` без
  браузера и бросает «запись закончилась», когда снимки кончились.
- `capture`: на каждый снимок `<dir>/<YYYY-MM-DD>/<seq>.json`, до `htmlPerSignature` санитизированных HTML на
  подпись экрана; старые дни удаляются сверх `maxMB`. `signature(snapshot)` → `{ hash (10 hex), shape,
  urlPattern }`. На диске настоящие страницы с чужими данными: папку держать вне git.

## Telegram (помощник, не часть ядра)

`telegram.js` окружение не читает: токен и группу передаёт вызывающий.
`telegramNotifier({ token, chatId, threadId?, apiBase? })` возвращает функцию для `connect({ notify })`;
`createTelegram(...)` → `send(text, { silent?, parseMode?, threadId? })` (деление длинных, повторы на 429 и 5xx,
переезд группы в супергруппу, токен не попадает в ошибки); `findChats({ token })` — группы, которые бот видел.
Для человека: `TELEGRAM_BOT_TOKEN=… node tools/telegram-chats.js` (группы и темы) и `… send "текст"`.

## Чего meatsuit не делает

- не решает, что нажимать, и не пишет тексты;
- не выполняет произвольный JS и не переходит на чужие хосты;
- не обходит капчу и не входит в аккаунты сам: на них стоп и сообщение человеку. Исключение — вход по
  одноразовому коду (`codeLogin`), который вызывающий получил от человека; пароль — всегда стоп;
- не подменяет отпечатки браузера;
- не хранит токены, ключи и пароли сайтов, не читает окружение.

## Обязанности проекта

- Держать свой `sites.json` и передавать его в `connect`; один `dir` на всех вызывающих одного браузера, и все они —
  на версии с очередями площадок.
- Ждать, что рядом идут задачи других площадок: ничто в своём процессе не должно считать себя единственным ботом.
- Использовать только последний `gen`; после `act` брать `gen` и `elements` из ответа.
- Проверять ответ модели до `act` (`validate` из `meatsuit/hands.js`).
- Не класть в журнал и в модель лишние данные чужих профилей.
- В `uploadDirs` класть только каталог с тем, что можно отправлять (резюме, письма): `upload` берёт оттуда любой
  pdf/doc/docx по выбору модели.
- Первый запуск на живой площадке — только `dryRun`.

## Ограничения

Не проверено живьём: руки ветки main, `upload`, `select` и многострочный `fill` в Chrome под Neko — все тесты на
фальшивых страницах в headless Chromium. Приёмка ПР2 предполагает одну живую dryRun-задачу в зеркале. Чтение по
запросу (`within`, `tree`, `items`) проверено только на сконструированных страницах (`test/eyes-read.test.js`);
страница Telegram Web K в нём собрана по тому, что план интеграции прочитал в исходниках tweb, а не по дампу живой
страницы.

Известное ограничение: элементы внутри чужих iframe (форма ATS на сайте компании) в снимок не попадают — идти
на хост формы напрямую.
